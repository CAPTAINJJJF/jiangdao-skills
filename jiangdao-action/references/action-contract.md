# 《IP 战略验证计划》合约

## 通用字段

1. 版本、日期、计划状态、起止时间和上游版本。
2. 当前层级：B1 / B2 / C；判断来源必须是 `jiangdao-ip`。
3. 本周期唯一经营问题与唯一关键结果。
4. 一个主要假设、一个调整变量及必要的最低、计划、挑战目标。
5. 里程碑与任务时间表：负责人、日期、依赖、交付物、指标和调整规则。
6. 真实反馈记录：内容流量、目标用户、咨询与问价、成交、拒绝、交付、成本与风险。
7. B 层按需生成《首次成交验证执行包》。
8. 公开内容是经营路径时生成《经营发布计划》和《操盘手内容任务卡》。
9. 停止条件和下一次经营判断时间。
10. 连续验证任务使用《7天分身接力计划》和《每日分身任务卡》；每7天完成一次真实验证闭环并由操盘手重新判断。
11. 飞书日历与 Codex 提醒的真实状态和ID。

## 分层证据链

### B1－账号启动验证

```text
已确认方向
→ 明确本轮内容验证问题与公开边界
→ 按最短路径复用或挖掘本人素材
→ 内容生产与真实发布
→ 回收内容、目标用户与执行反馈
→ 操盘手判断下一周期
```

账号启动验证允许定位、产品、价格与 CTA 为空，但必须明确“本轮不做成交”。发布事实只说明完成公开表达；是否继续当前方向取决于目标用户反馈、执行体验和后续重复证据。

尚未正式做账号的小白，首个7天周期必须完成：账号启动、至少一次真实拍摄、至少一次真实发布、反馈回收和第7天经营判断。这五项共同构成最小启动单位；方向可以暂定并在反馈后调整，访谈、研究、样本收集和精细定位不得替代首次拍摄与发布。

### B1－产品形成与 B2－首次成交

```text
方向
→ 定位与最小产品
→ 最快可行渠道
→ 《首次成交验证执行包》
→ 目标用户联系、咨询与适配判断
→ 真实成交或高质量拒绝
```

成交必须有可核验付款或等价交易事实；课件、报价、意向和模拟不算。一次成交允许操盘手判 C，但不证明交付效果或长期需求。

### C：首次交付、增长与业绩放大

```text
真实成交
→ 首次交付结果、成本与风险
→ 有限重复销售与交付
→ 一项主要增长或放大实验
```

已成交待交付或已交付待验证时先做首次交付验证。公开内容是获客路径时，依次判断“内容有人看吗、来的是目标用户吗、目标用户愿意付费吗”；咨询、问价和私信用于诊断精准人群到付费之间的卡点，不单独形成第四层经营信号。私域或已有关系直达客户时，直接读取真实接触、适配、报价与付款记录。不得在目标用户不足时仅凭零成交断言产品失败，也不得在付费弱时只要求扩大流量。

## 《首次成交验证执行包》

- 首批适配对象、真实关系和选择依据；
- 逐人首次联系候选及用户确认状态；
- 需求、紧迫度和适配判断问题；
- 根据对方原话组织的产品介绍要点；
- 跟进建议、时间点和停止条件；
- 真实回复、咨询、问价、报价、成交、拒绝理由和付款证据；
- 本轮主要瓶颈和一个调整变量。

执行包随真实回复增量更新，不提前编造对话。一次口头支持、模拟付款或未确认意向不算成交。所有联系、报价、承诺、收款和交付动作由用户确认。

## 《经营发布计划》

- 当前经营目标与重点回答的一个问题：内容有人看吗 / 来的是目标用户吗 / 目标用户愿意付费吗；
- 本轮内容组合、顺序及每类内容承担的人群识别、问题信任、能力证明或产品邀请任务；
- 统一 CTA、私域或产品承接；
- 观察指标、一个调整变量、停止条件和下一次判断点；

操盘手决定经营节奏；内容编导根据计划生成每条具体选题、结构、逐字稿与生产排期；`jiangdao-publish` 根据成片生成平台发布清单、候选、授权状态、上传结果与留痕。

《经营发布计划》和《操盘手内容任务卡》不得包含已经替用户确定的具体选题或标题。操盘手可以规定内容角色、目标人群、问题范围、验证目标和内容顺序；具体命题必须由内容编导与用户通过选题共创确认。

## 《操盘手内容任务卡》必填项

- 当前 B1/B2/C 层级和本轮唯一经营任务；
- 内容任务模式：内容方向验证 / 获客内容 / 放大内容；
- 已确认方向、目标人群假设、持续主题、核心问题或本轮验证问题、战略假设和不承担的任务；内容方向验证模式允许定位为空；
- 本轮希望研究或表达的经营问题；不填写赛道关键词矩阵；
- 经营上优先的平台或渠道及原因（如有）；具体搜索词、双平台采集和样本数量由内容编导决定；
- 首批认可的账号、视频或图文样本（如有），只作为内容编导转换赛道关键词和研究范围的输入；
- 本人证据、敏感事实、公开边界和禁止表达；
- CTA、私域或产品承接方式；没有承接时明确写“本轮不做成交”；
- 用户需要确认的选题、事实、发布、客户联系和报价闸门。

B1 账号启动把方向、目标人群假设、持续主题、验证问题和公开边界交给内容编导，并明确“本轮不做成交”。其他 B/C 模式根据最快路径说明短视频、直播、私域或已有关系的经营优先级，不接管内容编导的关键词职责。方向探索期的样本和对标研究由操盘手通过方向 Skill 调度，不进入本行动计划。

《操盘手内容任务卡》只负责交清“为什么搜”。内容编导在首个研究节点生成关键词确认区：核心赛道词由用户首次确认后复用；本轮任务词、相邻可用词和排除词由内容编导根据验证问题与样本召回结果动态更新。

## C 类诊断提示

| 观察 | 优先检查 |
|---|---|
| 内容少人看 | 触达、传播进入理由、渠道与内容表达 |
| 有人看但目标用户少 | 人群边界、场景、问题和表达精准度 |
| 目标用户出现但无人付费 | 问题紧迫度、产品结果、信任、价格、销售沟通与适配 |
| 已成交但交付未验证 | 客户起点、结果、满意度、耗时、成本、边界与风险 |
| 销售和交付已有阶段性重复证据 | 当前一个增长或放大瓶颈 |

不使用统一行业转化率硬判；优先使用当前项目历史基线和本轮可比数据。

## 极简执行卡

```text
当前阶段：
-

操盘手判断：
-

现在只做：
-

回来反馈：
-
```

每栏最多1—3条；“现在只做”写清执行者、动作与交付物，“回来反馈”写清需要带回的真实材料。

## 7天分身接力计划

### 生成前置条件

- 新账号学员已经确认一个足以开始的职业、行业、业务或内容锚点；
- 操盘手新提出的方向或内容路线已经经过一轮用户校准，并留下明确接受或修正后的确认；
- 操盘手已经确认公开边界，并按实际情况交接已有首批认可样本与可借鉴形式；无首批样本时交给内容编导补齐，不以凑齐关键词或样本数量作为7天计划前置，也无需先完成精细人群定位；
- 已有业务学员可以使用已确认的商业锚点与唯一经营问题作为输入；
- 任一前置条件缺失时，退回操盘手继续对聊，不生成7天计划，也不把前置研究计入第1天。

### 周期规则

- 每个周期只处理一个关键卡点、一个验证目标、一个主要假设和一个调整变量；
- 首次生成时展示完整7天接力关系；具体任务依赖真实资源与当前路径，不套统一内容数量；
- 新账号默认从已确认方向的内容交接开始；已有业务者可以跳过本人素材或账号基础任务；
- 小白首周期必须明确包含账号启动、首次拍摄、真实发布、反馈回收和第7天判断；需要继续了解用户时安排在不阻塞拍摄的位置；
- 赛道关键词尚未确认时，首个内容编导节点必须完成“方向转关键词”并将确认结果作为样本研究的依赖；该节点不得扩张为新一轮抽象定位；
- 小白首周期必须安排内容编导与用户共创确认选题；操盘手只交付内容任务卡，不直接定题；
- 真实发布后必须安排内容编导保存数据快照并形成《发布复盘卡》，再交操盘手完成第7天判断；
- 操盘手分身、内容编导分身、本我分身和对话搭子按需加入，不强制每个周期全部出现；
- 主责分身按任务依赖安排，同一分身可以连续主导多天，不为展示接力而按天轮换；
- 操盘手锁定经营目标和验证问题，各专业分身根据当前瓶颈、已有材料和任务依赖，自主选择职责范围内的方法与连续节点；
- 第7天候选主张为继续、调整、换节点或暂停；7天只承诺完成一次真实验证闭环。

### 7天接力字段

每天必须写清：日期或相对天数、当前节点、今日目标、主责分身、启动指令、分身交付物、本人现实动作、完成标准、建议时间块、依赖、回来证据、调整条件和下一位接力。

- 操盘手分身：判断节点、生成和更新计划、处理经营反馈；
- 对话搭子：当新内容需要多维挖掘完整故事时，围绕一个明确主题独立深聊，并把完整记录交回内容编导分身；
- 本我分身：在故事需要沉淀为长期人格资产，或涉及身份、价值与公开边界判断时加入；
- 内容编导分身：方向转关键词、研究、选题、脚本、拍摄指导、剪辑与内容复盘；
- 本人现实动作：拍摄、确认、发布、联系客户、报价、成交和交付。未经确认不得把现实动作标成已完成。

素材路由遵循四级顺序：已有可用素材直接交内容编导；只缺一个简单事实由当前角色补问；缺少完整故事时经用户同意交给对话搭子；需要长期人格沉淀或身份与价值边界判断时再加入本我分身。对话搭子的当次完整记录必须成为内容编导的明确输入。

上一任务的交付物必须成为下一任务的明确输入。没有依赖关系的任务不得为了凑满7天强行排列；可以安排等待真实数据，并写清回收时点。

```text

-

-

-
```

## 更新规则

- 根据操盘手判断只调整未来任务；历史日期、结果、成交、拒绝和风险不覆盖。
- 每轮只执行一个调整变量；单个反馈先记为线索，结合反馈来源、真实环节和重复程度再改变计划。重大风险除外。
- 反馈可能改变 A/B/C 时先交给 `jiangdao-ip`。
- 未经授权不创建提醒、日历、发布、客户消息、报价或成交动作。
- 更新未来日程与提醒前先检查现有项目，避免重复创建。
- 连续两次出现同类卡点时暂停机械顺延，先交操盘手判断任务设计、资源、依赖或方向假设。
