# 视频剪辑公共执行合约

本文件只保留所有路线共用的状态、路线锁、缓存、确认、超时和验收规则。路线专属细则按锁定结果再读取。

## 1. 单一真源与路线锁

```text
工作流待展开
→ 工作流待确认
→ 工作流已确认
→ 等待原片
→ 已收原片待检查
→ 路线已锁定
→ 已转写 / 代理已上传
→ 结构与删减待确认
→ 已确认待粗剪
→ 粗剪待验收
→ A-roll 已完成
→ 待包装 / 待剪映交接预检
→ 剪映交接构建中
→ 最终成片或工程待验收
→ 可交发布
```

每个剪辑任务只维护一份 `EDITING_STATE.json`。它是已确认工作流、阶段、活动项目、活动时间线、交付范围和验收口径的唯一主档；较长的 manifest、TASK、审核页和聊天记录只提供证据。每次继续剪辑、切换工具或开始整条渲染前，先读回该文件，再运行 `scripts/validate_editing_state.py`。状态卡缺失时先从实际工程和已有产物重建；信息冲突时停在读回阶段，不能凭聊天记忆选版本。

状态卡保持短小，只保存：`task_id`、`updated_at`、绝对 `project_root`、已确认工作流类型/版本/摘要、当前 `stage`、`route_lock`、本轮 `scope.delivery` 与 `scope.acceptance`、ChatCut 项目和正式时间线身份、三项能力预检、剪映 `handoff.mode` 与目标路径，以及五个互不替代的证据布尔值。详细切片和媒体清单仍写入 manifest。

```json
{
  "schema_version": "1.0",
  "task_id": "JD-VIDEO-001",
  "updated_at": "2026-09-03T20:00:00+08:00",
  "project_root": "/absolute/task/root",
  "stage": "workflow_confirmation",
  "workflow": {"type": "demo", "version": "V1", "summary": "保留操作步骤与旁白同步；隐私遮挡；演示完成后进入包装", "confirmed_at": null},
  "route_lock": "not_selected",
  "scope": {"delivery": ["base_video", "motion_overlay", "subtitles_srt"], "acceptance": "时长与正式时间线一致；额外素材为0；剪映实播通过"},
  "chatcut": {},
  "capabilities": {},
  "handoff": {"mode": "not_selected", "output_paths": {}},
  "evidence": {"assets_imported": false, "tracks_created": false, "captions_on_timeline": false, "draft_saved": false, "playback_checked": false}
}
```

## 2. 工作流确认门

每次开始新视频都先展开一份《剪辑工作流确认卡》。只允许读取用户要求、文件名、媒体时长/分辨率等轻量信息来形成方案；确认前不转写、不上传、不建时间线、不生成动效、不渲染。

确认卡必须覆盖：

- 视频类型与目标：定稿口播、课程、演示、访谈或混合型；
- 素材角色：主画面、主声音、录屏/PPT、演示证据、补录和保护区间；
- 内容逻辑：保持顺序、允许重组、删除边界和必须人工确认项；
- 画面逻辑：对轨方式、主次画面、演示与旁白同步、包装及字幕；
- 工具路线与降级方案；
- 阶段顺序、每个用户确认点、最终交付物和验收口径。

不同类型至少处理这些差异：

- `scripted_short`：确认稿为语义基准，保持顺序，先内容删减，再节奏、字幕和包装；
- `course`：先锁主声音与多源对轨，保留教学论证和连续对话，再处理章节、PPT/录屏、课程画框、字幕与长视频分段验收；
- `demo`：操作步骤和画面证据优先，旁白必须与操作同步，保留等待结果所需时间，先做隐私遮挡与演示完整性判断；
- `interview`：先确认说话人、核心观点和证据，结构重组必须单独获批；
- `mixed`：逐段标记采用哪种逻辑，再确认统一主时间线和最终交付。

用户明确回复同意当前工作流后，写入 `workflow.confirmed_at`、锁定 `workflow.version` 与 `route_lock`，阶段进入 `workflow_confirmed`。任何会改变内容顺序、主声音、演示证据、目标工具、交付轨道或验收的变更，都生成新工作流版本并重新确认。

任务记录必须保存 `workflow.type`、`workflow.version`、`workflow.confirmed_at`、`route_lock`、`route_version` 和 `route_changed_reason`。使用 ChatCut 时还要保存 `surface_lock=desktop|web` 和操作端变更原因。交付成片时保存 `export_mode=local|cloud`；只转可编辑工程时保存 `export_mode=not_applicable`。从 `full_package` 进入剪映交接时只推进 `stage` 并锁定 `handoff.mode`，不因一次导出尝试重写整条路线。失败时保留原片、已有产物、游标、失败原因和下一步。

## 3. 任务记录

长任务记录至少保存：

- 任务 ID、创建时间、更新时间；
- 原片绝对路径、大小、只读指纹；
- 确认稿、素材类型、目标平台和交付物；
- 活动路线、路线版本、ChatCut 操作端、适用时的导出模式、代理路径、ChatCut 项目/时间线或剪映草稿；
- 源媒体 codec、profile、pix_fmt、分辨率、帧率和音视频时长；
- ASR 服务、结果路径和缓存命中状态（发生转写时）；
- 用户确认版本、输出版本与最终字幕；
- 媒体、内容、字幕、真实播放的验收结果；
- 各阶段开始/结束时间、超时和失败次数，便于定位耗时。

状态卡中的五个完成证据必须分别更新：

- `assets_imported`：素材已出现在剪映媒体库；
- `tracks_created`：预期视频/音频轨已落到时间线；
- `captions_on_timeline`：SRT 已生成可见文本片段，不能用“已选择文件”代替；
- `draft_saved`：当前目标草稿保存后已重新读回；
- `playback_checked`：在剪映中实际播放过规定检查点。

后一个状态不能自动推导前一个状态。每次工具或人工操作后只更新实际有证据的字段。

## 4. 四条路线

### `local_a_roll`

适合只需干净口播、审核页和 SRT 的短中视频。锁定后读取 `local-a-roll-contract.md` 与 `jiangdao-transcribe`，其他路线无需加载这两份细则。

### `chatcut_edit`

适合 ChatCut 可编辑时间线、多版本比较或直接成片。锁定后读取 `chatcut-desktop-contract.md`。已安装桌面版时默认 `desktop + local`；需要分享链接、云端预检/渲染或用户明确要求网页时使用 `web + cloud`。桌面版先验证本地原片性能，必要时使用代理；网页路线默认代理。内容确认与删减都在同一条活动时间线完成。

### `chatcut_jianying`

适合课程长视频和后续剪映精修。锁定后完整读取 `jiangdao-chatcut-jianying`，严格执行：

```text
原片只读
→ 同内容轻量代理
→ ChatCut 初剪
→ 用户确认活动时间线
→ 读取完整片段清单
→ 新建剪映草稿
→ 素材引用关联回本地原片
→ 剪映真实播放抽查
```

ChatCut 初剪、完整包装和剪映交接都可以进入该子 Skill；已有正式包装时间线时沿用原 `route_lock`，并在状态卡把当前阶段写为 `handoff_preflight`。

### `full_package`

只接收已确认并验收的 A-roll。分镜、预览、动画和最终导出均为下游阶段，不与内容粗剪并行启动。

## 5. 确认语义

- “可以剪”“按这个来”“这个版本可以”代表当前审核版本获批；
- 局部修改只更新受影响区间，回显新版本后再执行；
- 用户只说“看看”“先出方案”或提出问题，不代表授权渲染；
- 上游稿件确认不等于剪辑结构确认，剪辑确认也不等于发布授权；
- ChatCut 初剪确认后，转换到剪映阶段不再二次做内容取舍。
- 用户确认选题、稿件或单个剪点，不等于确认整条剪辑工作流。

## 6. 时间与算力控制

- 同一原片指纹和同一阶段产物有效时直接复用；任务恢复从最近有效状态继续。
- 新参数或新工具先在 1—3 分钟代表性片段验证，再跑全片。
- 内容锁定前不做字幕样式、动画、完整导出或多版本渲染。
- 整条渲染前一次性完成：剪映安装/版本探测、ChatCut 当前账号或会员能力、透明 Motion Graphics/alpha 能力和目标输出路径可写检查。
- 能力限制第一次出现后，立即记录限制并锁定已授权降级模式。相同参数、相同失败原因的整条渲染不得再次启动。
- 尽量通过时间线清单、轨道白名单、1—3 分钟代表片段和已有成片完成验证；只有交付层内容或编码发生变化才重渲染整条。
- 上传、读取时间线、渲染或转写首次超时时，保存当前游标和已完成产物。
- 禁止用完全相同参数连续重跑整条任务。优先分页、分段、降低代理体积、恢复连接或缩小范围。
- 每个阶段只保留一个当前审核入口。废弃版本标记作废，后续不再引用。
- 所有新建的逐字稿删减与编排审核入口统一调用已安装的 `course-cut-review`；旧审核页生成器只用于历史项目兼容。审核页确认并导出方案后，才允许把内容删减应用到复制的时间线或正式粗剪。
- 工具“成功”只代表该步返回；真实文件、活动时间线和播放器结果才进入验收记录。

## 7. 通用验收

### 媒体

- 文件可读、时长大于零、全片可解码；
- 音视频流时长一致或差异原因已定位；
- 分辨率、比例、帧率、编码、profile 和 pix_fmt 符合任务；
- 音画同步，片头未误切，片尾包含最后一句和必要动作余量；
- 已抽查关键剪点、分卷边界和片尾。

### 工程

- ChatCut MCP 工作时间线、桌面当前可见时间线和状态卡正式时间线三者一致；
- 转换 manifest 只包含交付白名单轨道；隐藏、静音或关闭可见性的 ChatCut 轨仍视为存在；
- `chatcut_edit` 的操作端、导出模式、活动时间线和本地交付文件属于同一版本；
- 剪映草稿为独立新版本，切片数、顺序、速度和总时长可追溯；
- 主视频素材均关联到指定本地原片，缺失素材为 0；
- 每次导入 SRT、改变混合模式或调整轨道后，重新核对总时长、轨道数、片头、中段、片尾、字幕首尾和额外素材数；
- 已在当前软件版本真实打开并播放开头、中后段和片尾。

### 最终交付

至少包含最终成片或工程、同版本 SRT、无时间码逐字稿、任务 manifest、验收结果和已知限制。全部必需验收通过后才进入“可交发布”。
