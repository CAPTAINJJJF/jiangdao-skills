# 内容编导分身调度合约

## 当前默认采集参数

| 参数 | 默认值 |
|---|---|
| 平台 | 抖音、小红书 |
| 时间窗口 | 最近 30 天 |
| 排序 | 平台可得条件下按点赞量降序 |
| 正式样本最低可见点赞 | 1000 赞 |
| 新赛道首次采集目标 | 合计 20 条合格样本 |
| 已有赛道后续采集目标 | 每轮默认新增 10 条合格样本 |
| 每条目标有效评论 | 3—7 条 |
| 小红书候选入口 | 第三方数据 API 或用户人工提交的链接/文件，先进飞书再由 AI 分析 |

这些是当前合同的唯一参数真源。用户可为单次任务明确覆盖；其他 Skill 和本文件后续步骤只引用“当前采集参数”，不重复写死数值。

- 1000 赞是正式爆款样本的默认硬门槛，按采集时点平台可见点赞记录。低于门槛的内容可以保留为候选或观察样本，但不计入正式样本、不进入正式拆解和赛道数据库。
- 新赛道第一次采集默认合计 20 条合格样本；已有赛道后续每轮默认新增 10 条合格样本。平台分配根据本轮任务、数据入口和证据缺口记录，不另设固定配比。
- 用户可以明确为单次任务修改平台、时间、点赞门槛或目标数。覆盖项必须在前台采集说明和运行记录中显示，不能静默降低标准。
- 小红书的数量、时间、点赞、全文与评论门槛保持不变；本轮只替换数据入口。不得因第三方字段不足就降低合格标准。

## 内容生产语料门

- 当前采集参数负责赛道研究、数据库更新和跨样本判断。新赛道 20 条、已有赛道每轮 10 条仍然有效，不作为每条稿件开工的统一数量门槛。
- 单条内容进入新逐字稿生产时，完整执行 `jiangdao-produce` 的 [单条内容生产资料门](../../jiangdao-produce/references/production-input-gate.md)。高保真改写、混合二创和灵魂创作分别判断，不再共用一个“达到当前采集目标”的条件。
- 正式市场样本与生产材料分开记录。全文完整、来源可追溯、与当前选题相关的材料可以服务单条生产；没有达到正式样本门槛时，不进入赛道数据库，也不支撑“爆款已验证”或“市场已经证明”的表述。
- `index_only`、标题、首屏、平台摘要和二手复述只能提供线索，不能作为主生产材料。
- 已完成拆解、与当前选题相关且证据状态仍可用的历史材料可以复用；记录来源、资料时点、在本稿中的功能和缺口。
- 用户直接提交单条内容时可以完成拆解、高保真改写、局部借鉴或单篇题源共创。单篇题源候选被选中后，高保真可以使用该篇完整原稿直接进入；混合二创还需独立补充输入；灵魂创作还需用户产生具体起点和核心判断。

- 历史查重范围、重复链接和递补记录；
- 每条样本的媒体、元数据、评论、ASR、逐字稿、语义复核和视觉复核状态，以及任务状态、内容证据类型、`content_ready / market_ready` 资格；
- 单条样本的标准链接/内容 ID、辅助内容指纹、拆解卡版本和复用状态；

- 当前阶段、交付物、失败项和下一步；

旧运行记录只提供线索，不能覆盖当前合同。恢复旧任务时，先按当前核心词、当前采集参数和证据完整性重新验收；只有用户删换过样本或存在异常样本时才读取人工裁决记录。

## 2. 搜索与样本准备

### 搜索词

- 核心赛道词由内容编导根据已确认方向、目标人群假设、持续主题、本轮验证问题和首批认可样本（如有）生成；首次由用户确认与方向是否一致，后续复用；
- 启动、恢复或进入新采集批次时，前台必须显示本轮使用的核心赛道词。存在当前版本确认记录时显示“复用”；缺少记录、新学员、课程演示或数据库重建时展示完整《赛道关键词确认区》并等待首次确认；
- 每轮任务词由内容编导动态生成，可包括人群、场景、问题、情绪、观点和产品线索；相邻可用词与排除词分开管理；
- 先用平台能稳定召回的短关键词搜索，再用人群、场景、问题与证据完整性筛选；不把长问题句作为唯一召回入口；
- 人格数据库只提供后续观点、故事、案例、原话和立场，不作为关键词决策依据。

### 平台采集

#### 小红书安全入口

平台可执行范围统一读取 [平台操作与发布方式合同](../../shared/platform-operation-contract.md)；本节负责采集与归档细则。小红书发布交接固定携带 `delivery_mode=manual_handoff`，主角色切换不会恢复账号直连。

小红书固定使用以下链路：

`第三方数据 API 或用户人工提交 → 飞书候选入站 → 去重/门槛筛选 → AI 精读入选内容 → 拆解与数据库增量`

- 可用入口：第三方 API 返回的结构化数据；用户在小红书 App 内手动分享的链接；用户或供应方导出的 CSV/JSON；用户提供的正文、字幕、截图、评论或媒体文件。
- 候选入站最低需要可追溯数据源与标准链接或稳定内容 ID；进入正式拆解仍需同时通过点赞与全文证据门槛。
- AI 只处理已进入飞书或当前任务资料包的数据。第三方返回标题或摘要时只能建立 `index_only`；完整正文、可信字幕、导出媒体或用户提供原文通过检查后才能升级。
- 禁止调用小红书登录态、Cookie、浏览器自动化、OpenCLI、Agent-Reach、逆向签名、MCP/CLI 或其他脚本自动搜索、翻页、浏览、查看、评论或发布。同样不得使用代理轮换、指纹伪装、隐身脚本或随机化节奏规避检测。
- 第三方数据源、飞书或导出文件不可用时，记录 `SOURCE_UNAVAILABLE`、保留已有候选和缺口并停止小红书分支；不请求用户为 AI 登录小红书，不回退到原直连方式。

按当前采集参数分别处理目标平台：

1. 使用当前时间窗口；
2. 在平台可得能力内按点赞量降序；
3. 先排除低于当前最低点赞门槛的候选，再按当前目标数量入选；
4. 用标准链接或平台内容 ID 与历史样本去重；
5. 发现重复时继续取后续排名直至补足或候选耗尽；
6. 记录作者、标题、发布时间、采集时点和可见指标；
7. 保存原视频或完整图文、视觉证据和来源。

平台无法严格排序、无法核验日期或候选不足时，交付实际结果并标记限制；不得静默扩大时间窗口、降低点赞门槛、改变赛道或用另一平台补足。候选不足时继续扩展当前方向内的任务词和相邻可用词；仍不足则明确缺口，不用低赞样本凑数。

### 评论和转写

- 每条样本按当前评论参数采集高赞有效评论；
- 优先保留具体场景、问题、情绪、补充故事、反对意见、自报身份、传播动作和咨询/承接信号；
- 重复评论、纯表情、无意义夸赞和营销灌水不作为独立有效评论；
- 视频/音频交给 `jiangdao-transcribe`；图文按原顺序保存标题、正文和图片信息；
- 小红书评论、正文、字幕和媒体只从第三方 API 响应、人工导出或用户提供的文件取得；缺失时记录证据缺口，不直连平台补抓。
- 多角色使用语义角色；身份不确定时只写角色A/角色B；
- 评论、视觉或指标不可得时明确缺口，不用作者正文替代用户语言。
- 抖音视频固定执行 [douyin-transcript-workflow.md](douyin-transcript-workflow.md)。内容编导必须亲自读取整条样本验收报告，分别维护任务状态、工件状态和 `candidate / content_ready / market_ready / index_only / failed`；`qualified` 只作为 `market_ready` 的兼容字段，不能只写“已交给转写 Skill”。

### 合格样本计数

- “每平台目标样本”按可进入正式拆解的合格样本计数，不按详情页或候选链接数计数。
- 合格样本同时满足当前最低点赞门槛与全文证据门槛；点赞不可得或低于 1000 的候选默认不计数。后续采集时点赞跨过门槛，可以用新的数据快照重新验收。
- 视频样本先明确内容证据类型。口播型需要完整逐字稿与语义复核；语音＋画面型还需要可核验视觉证据；纯画面型需要完整 OCR、逐镜记录或等价视觉证据，ASR 可以标 `not_required`。图文样本需要按原顺序保存完整正文。标题、首屏、二手摘要和平台章节摘要只能建立候选索引。
- 只有索引证据的候选标 `index_only`，不得进入正式拆解卡、后台《爆款借鉴索引》和跨样本结论；继续从当前排名递补，直到达到目标数或候选耗尽。
- 前台和运行记录分别显示 `候选数`、`合格数/目标数`、`索引层数量` 和 `失败数量`。候选耗尽时交付实际合格数及每条失败原因。
- 转写完成还要核验原媒体字节数、可解析时长、ASR 状态、识别段数、首尾覆盖、重复/异常字符、文字密度和语义可用性；画面参与理解时继续核验视觉证据。任一必要项不可得时保留为 `candidate` 或 `content_ready`，不静默升级为正式市场样本。
- `scripts/check-douyin-transcript.js` 只提供逐字稿自动质量检查；抖音正式样本以 `scripts/check-douyin-sample.py` 输出的 `qualified=true` 为最终凭证。正式拆解卡数、后台借鉴索引中的抖音样本数和 `market_ready` 数必须一致。

## 3. 阶段与交接

发布相关职责固定分层：操盘手分身形成《经营发布计划》，内容编导分身形成具体内容生产计划，`jiangdao-publish` 形成平台发布清单。内容编导分身接收经营目标、内容组合与顺序、CTA 和调整条件后，负责具体选题、结构、逐字稿与生产排期，不改写上游经营决策。

| 阶段 | 最低输入 | 主输出 | 停止条件 |
|---|---|---|---|
| 方向与关键词 | 已确认方向、目标人群假设、持续主题、本轮验证问题与公开边界；定位按任务模式选填 | 首次为完整《赛道关键词确认区》；后续至少显示本轮复用的核心赛道词 | 首次等待用户确认；已有当前版本记录时展示后直接继续 |
| 内容方向验证 | 目标人群假设、持续主题、本轮验证问题、公开边界、“本轮不做成交” | 具体选题、脚本、生产排期与真实发布后的内容反馈 | 形成可交回操盘手的真实内容或执行证据 |
| 目标平台样本准备 | 核心词、本轮任务 | 目标平台合格样本、索引层候选与证据；小红书经安全入口先进飞书 | 合格数达到目标，或候选耗尽并披露缺口 |
| 样本展示 | 样本、原文、评论、视觉、数据 | 合格样本清单与证据缺口 | 展示后自动继续；用户删换样本或出现异常风险时暂停 |
| 爆款拆解 | 合格样本 | 面向用户的《逐篇爆款拆解》与后台内容池 | 拆解完成 |
| 市场数据库 | 十步拆解卡、批量内容池 | 已自动写回的赛道理解、问题池、用户语言、传播规律、后台加工库与《爆款借鉴索引》 | 写回完成；选题仍需用户选择 |
| 内容种子调取 | 当前人格数据库、赛道数据库、方向定位与近期经营任务 | 《内容种子候选清单》 | 用户确认一条并进入赛道证据匹配，或确认本轮没有可用种子 |
| 选题加工 | 当前赛道问题池中的完整问题句、当前任务与《经营发布计划》（如有） | 按共享前台格式合同生成《选题候选清单》 | 用户选中题目 |
| 生产决策 | 已选题目、题源证据与当前IP材料 | 按选题合同生成的《生产决策卡》 | 用户整体确认一次 |
| 内容生产 | 通过《单条内容生产资料门》的当前资料包、已确认《生产决策卡》与公开边界；单条明确高保真以完整来源和用户明确指令替代前台卡片 | 用户确认的可拍摄逐字稿 | 用户确认逐字稿并完成拍摄 |
| 视频剪辑 | 拍摄原片、确认逐字稿或完整访谈素材 | 结构/删减审核页、同版本成片与字幕 | 用户确认结构后完成剪辑与成片验收 |
| 发布交接 | 已通过验收的成片与对应逐字稿/字幕 | 成片版本、逐字稿及经营计划/任务卡索引 | 自动交回操盘手分身，由操盘手调用 `jiangdao-publish` |
| 发布 | 已选发布组合与明确发布授权 | 真实发布链接与版本 | 平台真实返回 |
| 复盘 | 真实链接、版本和数据 | 《发布复盘卡》 | 下一轮判断形成 |

不得把上游确认推定为下游授权。

## 4. 单条爆款连续处理

用户主动提供一条内容并要求分析或改成选题时，按以下顺序运行：

1. 用平台内容 ID 或标准链接匹配历史样本；链接不可得时，再用作者、标题、开头和规范化正文指纹辅助判断。
2. 没有当前版本拆解卡时先调用 `jiangdao-deconstruct`；已有时明确显示“复用已有拆解”及来源，不重复拆解，也不静默跳过。
3. 前台严格使用共享格式合同中的 01—10《逐篇爆款拆解》推理链；完整后台证据与关联字段不另起平行前台栏目。
4. 单条样本完成拆解后，把合格的赛道问题及来源索引写入当前赛道问题池。用户明确要沿当前文章继续时，调用 `jiangdao-adapt-topic` 的 `single_source` 模式并锁定该篇的一个问题；用户发起常规赛道选题时，调用 `track_pool` 模式，题源不足则返回 `TRACK_POOL_SCOPE_INSUFFICIENT`，不自行降级。
5. 用户先选择题目方向。单篇题源共创被选中的题目可以保存，再按生产模式预检并装配材料：高保真使用该篇完整原稿，混合二创补独立输入，灵魂创作补用户原始内容。标准任务材料齐备后形成并确认《生产决策卡》，再运行最终资料校验；明确的高保真任务按快速通道执行。

后台产物保持独立：

- 原样本的《爆款样本拆解卡》可以被不同IP重复使用；
- 《选题候选清单》和后台生产决策记录必须关联具体IP、方向版本和任务；
- 不能把某个IP的改造判断倒写成原爆款的客观拆解结论。

用户直接提供单条内容，代表该条样本已被选择进入分析；批量任务中的合格样本清单用于透明展示和删换，不再默认阻塞拆解。形成有效证据后的数据库增量属于后台自动维护，不另设授权，也不授权生产或发布。

## 5. 合格样本清单

前台清单严格使用共享的 [内容编导前台文本格式合同](../../shared/content-frontstage-format-contract.md)，本合同只维护采集与合格判断，不重复定义字段。

清单展示后连续进入拆解。用户可以随时替换或删除样本；出现点赞不可核验、正文归属存疑、争议风险或明显偏离赛道等异常项时，内容编导只就异常项暂停并说明需要用户决定什么。不得用笼统的“请确认后继续”制造额外轮次。

## 6. 跨样本市场研究

合格样本清单展示后逐条调用 `jiangdao-deconstruct`，先完成 01—10《逐篇爆款拆解》、后台《爆款借鉴索引》和结构化单条增量。随后由 `jiangdao-content` 按 [赛道数据库统一模板](track-database-template.md) 和 [通用编译合同](track-database-compilation-contract.md) 完成去重、跨样本归并、价值审计、状态升降级和来源关联；拆解子 Skill 只提供单条候选增量。编译与独立校验通过后才切换正式数据库入口。

作者答案、观点、方法、框架、实际推进链、表达、故事和人物机制继续保存在十步详情、《爆款借鉴索引》和来源关联中。证据缺口单独记录，不为了填满模块补造结论。

面向用户的逐条研究结果仍使用共享格式合同规定的 01—10《逐篇爆款拆解》；赛道数据库首页按赛道分段展示四部分赛道认知。短期内容空位留在当前任务中，不扩成数据库栏目。

## 7. 题源证据与选题处理

- 单篇题源共创与赛道问题池共创的模式资格统一交给选题合同；进入新逐字稿前按《单条内容生产资料门》执行。
- 完整选题共创对赛道问题池的读取、校准、加工和停止条件，统一交给 `jiangdao-adapt-topic` 的 [选题合同](../../jiangdao-adapt-topic/references/topic-candidate-contract.md)；本合同不复制其问题筛选、发展路径和底层加工动作。
- 调取内容种子时，完整执行共享的 [内容资产捕捉与跨库关联合同](../../shared/content-asset-capture-contract.md)；赛道题源与人格题源继续分开保存。

### 内容种子联合查询

联合查询、排序、最多展示数量、跨库 `seed_id`、成熟度和确认后的状态更新，全部执行共享内容资产合同。调度层只记录本轮调用、来源版本和写回结果，不维护第二套查询步骤。

## 8. 资料保存

### 样本资料包

集中保存链接、原媒体、逐字稿/图文原文、评论、数据快照、视觉证据和单条拆解卡。本地自动保存；当前项目已配置飞书赛道库时按归档合同自动写回，不逐轮确认。

新建、迁移、更新或导出赛道数据库时，必须完整读取 [赛道数据库统一模板](track-database-template.md)；正式生成爆款详情页时继续读取 [赛道数据库爆款详情页标准](track-database-detail-page.md)。详情页固定使用“来源与数据 → 推送语与推送标签 → 完整逐字稿 → 赛道问题 → 选题怎么来的 → 原选题 → 作者答案 → 为什么能传播 → 评论区洞察 → 最值得拿走”的 10 步顺序；内容必须来自 `jiangdao-deconstruct` 当前版本拆解卡并保持同步，不能由总控临时另写一套简评。

### 本地《赛道与内容数据库》

正式项目统一使用四部分赛道认知库、后台选题加工库、十步单篇详情证据层和自动关联。目录、字段、聚合责任、迁移与验收全部引用 [赛道数据库统一模板](track-database-template.md)，本调度合同只维护何时写回。

搜索词、候选清单、短期内容机会、失败记录、某次任务的选题确认、内容生产、发布与复盘状态保存在对应内容编导任务资料包，通过后台索引关联；它们不作为赛道数据库栏目。旧版“高价值选题池”“当前内容机会”“赛道总览＋爆款原料列表”只允许作为迁移前快照读取，不能继续写入。

原媒体、逐字稿、评论、视觉证据、数据快照和单条拆解卡继续留在对应任务资料包作为证据附件；详情页必须同时内嵌完整逐字稿/正文/OCR、已取得的评论原文和同版本拆解，不能让用户跨目录才能完成阅读。

### 增量触发

正式样本入库、旧样本重拆、选题使用或真实发布复盘形成新证据时，由内容编导按数据库模板执行增量聚合并记录更新前后数量、状态变化与来源缺口。重复材料不制造版本；冲突证据保留修订关系。首页不追加运行日志或某次内容生产进度。

每当搜索、拆解、选题或发布复盘形成实质新增或修正时自动增量写回，不询问“要不要更新数据库”。重复材料或无新增认识时不制造版本；新证据与旧结论冲突时保留时间、来源和修订关系，不静默覆盖。

不得把外部演绎故事写进人格数据库，或将AI推断写成用户真实经历。

### 每日复盘只读接口

本我分身可以只读《赛道问题池》和《用户语言与评论问题库》，为每日复盘的候选话题选择一条“赛道来信”；用户选中后，本轮只推进这一题并生成对话搭子大纲。返回字段只包括：

- 目标人群与具体场景；
- 原始问题或代表原话；
- 来源链接、样本或评论索引；
- 证据状态：有来源 / 候选待验证 / 证据不足；
- 最后更新时间或当前资料时点。

选择时优先匹配当前已确认方向、定位或近期内容任务，不把出现次数写成市场强度。这个只读动作不启动搜索、下载、拆解或选题，不修改数据库，也不把 AI 生成的问题冒充市场事实。没有可追溯问题时返回“赛道数据库暂无可用问题”。

## 9. 手动与自动

- 默认每轮由用户手动启动；
- 一轮任务启动后，关于本人的增量自动交给本我分身写回人格数据库，市场增量由内容编导分身写回赛道数据库，不需要再次授权；
- 一次任务中的搜索、下载、转写、评论准备、合格样本展示和逐篇拆解可以连续执行；
- “本轮连续执行”不等于“每日自动执行”；
- 共享捕捉只处理当前 Skill 已获得的材料，不监听其他聊天；其他会话需由用户提交记录、链接或产品集成显式传入。
- 只有用户明确要求时才创建周期自动化，并确认频率、平台、时间窗口、项目范围和通知方式；
- 周期任务若包含小红书，只能周期调用第三方数据 API、导入人工导出结果和写回飞书；不得调度任何直连小红书账号的工具。
- 自动化完成采集与证据准备后可以继续拆解和数据库写回；涉及选题选择、生产决策、剪辑和发布时仍遵守对应人工闸门。

## 10. 前台状态

最终前台严格使用共享的 [内容编导前台文本格式合同](../../shared/content-frontstage-format-contract.md)。本节只保留“一次一个主结果、一个下一步”的状态约束，不再另列字段。

运行记录、逐字稿、评论文件和媒体目录保留在后台，由主入口索引。

用户明确沿当前文章继续时，单条爆款连续任务可以依次推进拆解、借鉴和单篇题源共创；前台显示单篇范围提示。每次回复仍只展示当前阶段的一个主交付物，不把拆解卡与候选清单塞进同一主结果。已有旧拆解但缺少当前传播判断时必须补做。批量研究归档任务优先展示《逐篇爆款拆解》，不自动用跨样本综合结论替用户决定新选题。
