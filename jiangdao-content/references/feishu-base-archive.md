# 飞书赛道库自动归档

## 归档目标

从当前项目的 `config/jiangdao-content-feishu-archive.yaml` 读取 Base、数据表和身份配置。Skill 只保存验证与写入流程，不保存某个工作区的 URL、token、Table ID、确认日期或本机路径。

配置缺失时保留本地数据库增量，并只询问目标库这个具体缺口。配置与实时解析结果不一致时报告结构漂移，不猜测或静默改写目标。

飞书 Base 继续承担外部样本归档和单条拆解字段承接。本地《赛道与内容数据库》负责跨样本赛道认知库与后台选题加工库。日常同步不得为适配本地聚合结构擅自增删飞书字段；先通过内容链接和本地 `record_id` 关联，再由本地聚合层读取证据。

## 触发与边界

- 小红书使用“候选入站 → AI 筛选/精读 → 同记录增量完善”两段归档。第三方 API 或用户人工明确提交的候选，拥有可追溯数据源与标准链接后，先以最小字段写入当前项目已配置的飞书赛道库；AI 只分析已入站候选。
- 每当任务最终入选一条带原始链接的爆款、对标内容或案例样本，并形成可核验原文、拆解或数据增量后，继续更新同一条记录，不重复新建，不逐轮确认。
- 链接不可核实、数据源不可追溯或仅作搜索噪声的内容不写入。已入站但未通过点赞或全文门槛的候选保留客观缺口，不升级为正式样本。
- 飞书赛道库是当前工作流的后台数据库；配置有效即视为数据库写回目标。用户明确要求本轮不写飞书时服从，但仍保留本地增量。
- 没有原始内容链接时不建记录；在交付中列入“待补链接”。
- 当前任务明确只做临时研究或用户明确要求不写飞书时，可以跳过，但运行清单和最终交付必须写“未归档”及原因。

## 写入流程

1. 用 `lark-cli base +url-resolve` 和 `+base-get` 验证 Base 名称。
2. 用 `+field-list` 读取真实字段；不要只依赖本文件中的旧快照。
3. 用 `+record-list --filter-json` 按「内容链接」精确查询；多条链接合并成一个 `logic=or` 筛选，避免并发查重触发限流。
4. 候选首次入站只写真实可确认的最小字段：内容链接、平台、采集日期、原始发布文案/作者/数据快照（可得时）、数据来源、证据限制与当前整理状态。选择项只使用实时字段中已存在的选项，没有合适选项时留空并把来源写入「证据限制」，不自动新建近义选项。
5. 新记录组装成一个 `+record-batch-create` 请求，单批不超过 200 条并保持串行写入；AI 筛选、取证和拆解形成新的可核验字段后，按记录 ID 增量更新同一条记录，不用空值、低置信度推断或较旧快照覆盖已有事实。
6. 用返回的 `record_id_list` 逐条 `+record-get` 或用精确搜索读回标题、链接与内容 ID。
7. 最终交付中分开报告“候选入站 N 条 / 正式入选 N 条 / 更新 N 条 / 无增量跳过 N 条 / 待补写 N 条”；失败时列出链接和原因。

若 `lark-cli` 不在 PATH，读取当前环境已配置的工具路径；不要假定用户目录下的固定绝对路径。不要把 OAuth token、app secret 或 access token 写入项目文件或回复。

## 当前字段映射

这张表只存外部爆款样本，不写我方发布、负责人或发布后增长数据。只写真实可确认的数据；字段不存在、变为只读或类型变化时跳过并报告结构漂移。

### 来源索引

| Base 字段 | 来源与规则 |
|---|---|
| 选题标题 | 飞书现有兼容字段名；填写答案开放的原选题简名，不直接照抄原标题或作者观点 |
| 原始发布文案 | 原平台原标题或发布文案；推送语与标签有独立字段时分开写，不可得则留空 |
| 作者账号 | 原作者或账号名；不可得则留空 |
| 内容链接 | 原始平台内容链接；唯一查重键；没有链接不建记录 |
| 平台 | 只使用字段中真实存在的选项 |
| 发布日期 | 原始发布时间；不可得则留空 |
| 采集日期 | 样本首次进入爆款库的日期 |
| 素材类型、内容类型、赛道、内容标签 | 只使用字段中已有选项；无合适选项则留空，不创建近义选项 |

### 数据证据

| Base 字段 | 来源与规则 |
|---|---|
| 作者粉丝数、播放量、点赞数、评论数、收藏数、转发数 | 只写来源可核验的数字，不换算、不估算 |
| 数据快照日期 | 上述指标实际对应的采集日期；没有指标时可与采集日期一致 |
| 数据来源 | 平台后台、第三方工具、人工统计、其他；按真实来源选 |
| 数据状态 | 指标完整且核验后写“已更新”；关键指标缺失写“待更新”；异常写“异常” |
| 爆款依据 | 只有存在相应数据证据时才写高赞、高评、高转发、高完播、低粉爆款等标签 |

### 内容拆解

| Base 字段 | 来源与规则 |
|---|---|
| 完整逐字稿 | 口播或语音＋画面内容有可用字幕/转写时写入无时间码完整文本；关键视觉信息另附并标核验状态。纯画面内容留空并在「证据限制」写明完整 OCR、逐镜记录或视觉证据入口，不生成假逐字稿 |
| 核心选题 | 写 `赛道问题 → 选题怎么来的 → 原选题` 的精简关联；原选题保持答案开放，原标题与作者答案另字段保存 |
| 目标用户与场景 | 写赛道问题面向谁、在什么阶段和场景发生，以及用户为什么在意 |
| 问题或情绪 | 统一写赛道问题与核心情绪；只有作者正文时标候选，评论/访谈/搜索等用户证据单独标明 |
| 开头钩子、内容结构 | 基于实际原文、转写和已核验视觉，保存推送语/标签、作者答案、内容框架和实际推进链；不把答案写进赛道问题或原选题 |
| 爆款机制 | 写自由的“为什么能传播”判断、支持依据、反证/替代解释和结论强度；四段传播链可以留在本地后台卡，不作为固定前台标签 |
| 评论区反馈 | 只写真实评论中的用户回应点、代表原话、对传播判断的验证/修正、新赛道问题、新选题线索和证据边界 |
| 证据限制 | 明确缺失的数据、评论、来源核验、案例真实性和样本代表性 |

### IP 迁移

| Base 字段 | 来源与规则 |
|---|---|
| 可挪用点 | 依据“最值得拿走”记录赛道问题、选题加工、作者答案、框架/表达、传播机制和评论线索，并保留来源、使用边界与本地完整卡入口 |
| 选题迁移 | 结合当前目标用户与本人证据后的新选题；缺少战略或人格资料时标为待判断 |
| 不可照搬点 | 记录需要重新造的表达、缺少作者身份支撑的内容，以及版权、事实或专业边界 |
| 适配结论 | 待判断、值得测试、需改造、不适合；AI 只给候选判断，用户最终决定 |
| 整理状态 | 待转写、待拆解、已拆解、待补数据；优先写当前最需要补的下一步 |

不要普通写入「内容ID」「创建时间」「更新时间」；它们是只读字段。

## 权限策略

日常自动维护需要读取 Base、数据表、字段和记录，并按增量创建或更新记录；优先批量查重、批量创建和最小字段更新。权限不足时保留本地增量并报告缺少的具体权限，不把“未同步飞书”误写成“数据库未更新”。字段增删改、表结构迁移、批量覆盖或删除仍须用户明确批准，不属于日常自动更新。
