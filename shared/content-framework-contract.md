# 内容框架识别、选择与执行合同

本合同是内容编导使用内容框架的唯一正式真源。框架负责组织已有内容价值，不生成题源、观点、经历或事实。六类框架只承担检索导航；真正进入选题建议和内容生产时，必须调用一张可执行的“机制卡”。

## 固定链路

`爆款拆解识别具体机制 → 形成/更新机制卡 → 选题后选择主机制卡 → 内容生产执行推进链 → 发布后复盘真实表现`

- 拆解阶段回答原作者怎样组织内容、每一步起什么作用，以及这套机制是否值得借；新机制写成候选机制卡，不替当前 IP 选择最终方案。
- 选题阶段先确认答案开放的选题，再按 [选题合同](../jiangdao-adapt-topic/references/topic-candidate-contract.md) 生成并确认一张《生产决策卡》；本合同只负责主机制卡与推进链进入其中的方式。
- 生产阶段按已确认机制卡分配素材和段落功能，不能只套一个大类名称。
- 发布数据只用于复盘当前内容的真实表现，不能证明某类框架必然带来流量或成交。

## 前台最小结果

选题候选阶段可以把“候选机制＋实际推进链”自然融入该题的建议段，不单独展开字段卡；此时只代表建议。用户选中题目后，在《生产决策卡》中锁定最终机制。

用户可见字段统一写入共享 [内容编导前台文本格式合同](content-frontstage-format-contract.md) 中的“建议”或“主机制与推进”，不得单独展开机制字段卡。所属框架大类、选择依据、可借部分和详细原料条件保留在后台；关键缺口统一进入《生产决策卡》的“原料缺口”。

## 识别原则

1. 同时判断“讲了什么”和“怎样讲”；选题与框架分开记录。
2. 原题不适合当前 IP 时，框架仍可借鉴；题目可借不代表必须沿用原框架。
3. 依据正文的实际推进识别机制，不按标题、作者身份或预设标签归类。
4. 一条内容只选一个主机制控制推进；辅助机制仅在确有第二种功能时记录，最多一个。
5. 词典名称匹配不准时，用朴素语言记录实际推进链，并标为“候选机制”；不得硬塞分类。
6. “人设”“信任”“流量”“引流”“成交”属于内容可能产生的作用或任务，不作为互斥框架。第一人称经历也不自动等于个人故事。
7. 纯粹围绕“我经历了什么、我如何变化”展开，才优先识别为故事代入型；围绕“我做过什么、由此总结出什么经验”展开，优先识别为实践复盘型。

## 六类框架导航

这些名称只用于粗筛和归档。它们不能直接作为生产指令，也不是已经验证的传播因果。具体执行读取 [内容机制卡词典](content-framework-mechanism-cards.md)。

### 观点立场型

适合表达判断、纠正常见认知或建立鲜明立场。

- `常见认知 → 具体问题 → 原因拆解 → 新判断`
- `错误做法 → 结果失效 → 原因拆解 → 正确立场`
- `结果反差 → 提出疑问 → 点出差别 → 提炼观点`

### 干货交付型

适合交付步骤、清单、方法或可执行动作。

- `结果先行 → 拆解步骤 → 重点提醒 → 总结收口`
- `具体问题 → 判断卡点 → 给出动作 → 适用边界`
- `先给结论 → 解释原因 → 例子或证据 → 落到行动`

### 痛点击穿型

适合让特定用户认出自己的处境，并解释问题为什么持续发生。

- `现象问题 → 持续痛苦 → 关键原因 → 解决出口`
- `表面问题 → 深层根源 → 影响后果 → 核心方向`

### 热点借势型

适合把公共事件、企业或人物映射回当前赛道问题，并给出创作者判断。

- `热点事件 → 提炼议题 → 映射用户问题 → 创作者判断`
- `热点对象 → 表面现象 → 底层解释 → 现实启发`

### 故事代入型

适合围绕个人经历、关系变化或成长过程建立真实感和人物记忆。

- `过去处境 → 关键事件 → 选择与代价 → 情绪或认知变化`

故事必须有事实归属和公开边界；故事只是证明材料时，把它记录为辅助框架或素材，不把整条内容归为故事型。

### 实践复盘型

兼容旧称“拆解复盘型”。适合把真实实践沉淀为判断、方法和能力证明。

- 项目复盘：`项目背景 → 真实卡点 → 判断过程 → 采取动作 → 结果与边界 → 认知变化`
- 阶段经验复盘：`做了什么 → 付出什么代价 → 分条总结经验 → 解释每条判断 → 给同行提醒`
- 结果复盘：`结果 → 关键节点 → 成败原因 → 可复用判断 → 下次动作`
- 成长复盘：`过去状态 → 关键选择 → 变化过程 → 当前心得`

项目过程、结果和事后解释必须分开。个案经验不能直接写成普遍规律。

## 框架可借鉴性

拆解阶段在选题借鉴判断之外，单独给出：

- **可直接借框架**：当前 IP 具备同类事实、经验或方法原料，可以复用推进链。
- **补原料后可借**：结构成立，但缺少本人经历、证据、案例或明确观点。
- **只借局部**：只借开头、某一段功能、清单组织或收束方式。
- **不建议借**：框架依赖原作者独占身份、事件或素材，迁移后会空洞或失真。

框架判断至少说明：需要哪些原料、当前是否具备、具体借哪一段。选题借鉴性与框架借鉴性不得合并成一个结论。

## 选择与生产

选题选中后，内容编导根据以下顺序推荐一张主机制卡：

1. 本条最重要的内容任务；
2. 已有原料最能支撑的推进方式；
3. 用户希望获得的价值；
4. 当前最需要避免的风险。

生产时把机制卡推进链转换成段落功能，并为每一段指定真实素材来源。缺少关键原料时在《生产决策卡》中集中显示，用户一次决定补材料、删掉该段或换机制；不再拆成多轮确认。用户确认后，除出现新事实风险或方案发生实质变化外直接完成初稿。

拆解、选题和生产都必须读取同一张机制卡：拆解负责抽取与更新，选题负责匹配，生产负责执行和验收。只写“观点型、干货型、复盘型”等大类，视为框架没有真正进入工作流。

框架词典不与三维检查表绑定。三维检查仍是独立候选工具，未被用户确认前不自动增加评分或前台字段。
