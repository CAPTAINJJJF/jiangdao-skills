# 平台操作与发布方式合同

本合同供操盘手、内容编导、转写与发布能力共用；平台允许的操作方式随任务交接保留。先判断平台方式，再检查本次任务授权。用户选择文案、同意发布或要求多平台同步，不自动改变既有平台方式。

## 小红书

- 内容发现与取证仅使用第三方数据 API 或用户人工提供的链接、导出文件、正文、字幕、截图、评论和媒体。链接只作为来源索引；只有链接而没有可读内容时，使用上述数据入口补齐或保留缺口。
- AI 不直连小红书账号：不使用登录态、Cookie、浏览器自动化、逆向签名、OpenCLI、Agent-Reach、MCP/CLI 或其他脚本自动搜索、翻页、浏览、评论、上传、保存平台草稿、定时或点击发布；不通过代理、指纹伪装等方式规避限制。
- 发布方式固定为 `manual_handoff`：可以自动准备标题、推送语、标签及对应成片清单，说明由本人在平台完成发布；不调用 `xiaohongshu-upload`，不发起账号登录检查或扫码。
- 用户说“选 A 并发布”时，保存已选组合与授权，完成可交付的人工发布材料，状态记为“待本人发布”；“选 A”仅保存选择。均不尝试自动上传，也不反复请求同一文案确认。
- 用户完成后，接收其提供的链接、内容 ID、发布截图或导出记录，并核对账号、成片版本、文案与状态。仅口头说完成或提供无法对应版本的记录时记为“本人反馈已发布，待核验”；有相符发布证据后才能记为“已发布”。不为核验恢复账号自动化。
- 本合同不新建采集计划或恢复已有暂停任务。第三方来源不可用时保留已有材料与缺口，不改走账号直连。

## 其他已支持平台

抖音、快手、Bilibili 使用 `authorized_upload`。在用户明确授权、本机具备对应执行能力且平台前置检查通过后，按各平台 Skill 上传；结果不确定时先核验，不自动重复发布。

## 多平台与记录

每个平台分别记录 `platform`、`delivery_mode`、成片版本、文案选择、授权、当前状态和发布证据。小红书人工交接不阻止其他已授权平台继续执行；一个平台完成不代表全部已发布。

共用状态：未选择、已选择待授权；之后分流为：

- `authorized_upload`：已授权待检查 → 上传中 → 已发布 / 发布失败 / 结果待核验。
- `manual_handoff`：待本人发布 → 本人反馈已发布待核验 / 已发布。

发布材料交付与真实发布分别验收。只有真实发布证据可进入正式发布复盘；单纯文案选择、平台草稿或用户意向不算已发布。
