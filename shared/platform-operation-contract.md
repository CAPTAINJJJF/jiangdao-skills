# 平台操作与发布方式合同

本合同供操盘手、内容编导、转写与发布能力共用。根据用户授权和实际执行能力记录平台方式，并随任务交接保留。

## 小红书内容发现与取证

- 内容发现与取证仅使用第三方数据 API 或用户人工提供的链接、导出文件、正文、字幕、截图、评论和媒体。链接只作为来源索引；只有链接而没有可读内容时，使用上述数据入口补齐或保留缺口。
- 内容采集不使用登录态、Cookie、浏览器自动化、逆向签名、OpenCLI、Agent-Reach、MCP/CLI 或其他脚本自动搜索、翻页、浏览或采集评论；不通过代理、指纹伪装等方式规避限制。
- 本合同不新建采集计划或恢复已有暂停任务。第三方来源不可用时保留已有材料与缺口，不改走账号直连采集。

## 发布方式

小红书、抖音、快手、Bilibili 均支持 `authorized_upload`。在用户明确授权、本机具备对应执行能力且平台前置检查通过后，按各平台上传 Skill 执行；也可使用用户指定且实际可用的发布工具。小红书可调用 `xiaohongshu-upload`，按任务需要检查登录、上传、保存草稿、安排定时、发布及核验发布结果。执行仍须遵守工具和平台的访问限制。

- “选 A”仅保存选择；“选 A 并发布”等明确表达可同时完成选择与授权，不反复请求同一文案确认。
- `manual_handoff` 仅用于用户选择人工操作或实际执行能力不可用时的交接，不按平台强制指定。交付最终文案与对应成片清单，记录“待本人发布”及原因。
- 账号登录、上传、草稿保存、定时与正式发布分别记录；用户只授权上传时，不推断已授权正式发布。
- 结果不确定时先核验，不自动重复发布。核对账号、成片版本、最终文案和平台记录；仅口头说完成或记录无法对应版本时记为“本人反馈已发布，待核验”。

## 多平台与记录

每个平台分别记录 `platform`、`delivery_mode`、成片版本、文案选择、授权、当前状态和发布证据。单个平台待处理不阻止其他已授权平台继续执行；一个平台完成不代表全部已发布。

共用状态：未选择、已选择待授权；之后分流为：

- `authorized_upload`：已授权待检查 → 上传中 → 已发布 / 发布失败 / 结果待核验。
- `manual_handoff`：待本人发布 → 本人反馈已发布待核验 / 已发布。

发布材料交付与真实发布分别验收。只有真实发布证据可进入正式发布复盘；单纯文案选择、平台草稿或用户意向不算已发布。
