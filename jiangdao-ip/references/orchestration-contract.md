## A / B / C 判层证据

| 证据 | 判层含义 |
|---|---|
| 没有本人愿意尝试的职业、行业、业务或内容启动锚点 | A |
| 本人已确认一个足以开始的启动锚点，尚无产品或需求信号 | B1－账号启动；先完成真实表达与反馈验证 |
| 本人已明确主要群体与持续主题，已有明确问题、需求信号或产品意图 | B1－产品形成 |
| 已有产品想法、课程大纲、课件或报价但未成交 | B2，不是 C |
| 有产品体系且存在可核验真实成交 | C；前台先进入首次交付验证期 |

判层只决定当前经营任务，不代表能力、市场或产品已经永久成立。

## 四轴经营诊断与启动路由

A/B/C 判层前先检查业务成熟度、IP 成熟度、当前经营目标和当前研究证据。四轴诊断描述用户从哪里启动，A/B/C 描述当前唯一经营问题，两者同时保留。

首次进入且业务证据、IP 证据或经营目标存在高影响缺口时，前台先使用“经营诊断中”。操盘手每轮只补一个会改变路由的事实，达到最低诊断证据后再宣布自然阶段。“经营诊断中”只是入口状态，不新增后台层级。

| 启动情况 | 优先动作 |
|---|---|
| IP 未启动，但已有本人愿意尝试的职业、行业或业务锚点 | 先了解同赛道视频与可借鉴形式，随即进入真实拍摄和发布；定位随反馈收紧 |
| 业务未验证、IP 未启动，且没有可用启动锚点 | 补本人证据、喜欢样本、对标账号和赛道认知，形成方向假设 |
| 已确认可用启动锚点、业务与产品尚未验证、IP 未启动 | 进入账号启动验证；先完成真实表达并观察执行与初步受众反馈 |
| 业务已验证、IP 待启动或增长，经营目标明确 | 保留现有商业锚点，围绕线上触达与内容承接推进 |
| 业务已验证、IP 待启动，经营目标不清 | 先确认给原业务引流、发展新业务或探索表达，再生成计划 |
| B 端项目已验证、线上获客待建立 | 先还原真实成交与交付链路，再研究对标账号的公开变现链路 |

喜欢的视频、对标账号和真实成交案例分别承担表达偏好、市场研究和商业验证作用。抽象能力标签可以作为差异点，未说明目标人群、问题和商业承接时不得直接充当赛道。

## 最小成本与最快反馈路由

| 当前情况 | 优先启动动作 | 本轮反馈 |
|---|---|---|
| 小白、账号未启动，已有可用职业或行业锚点 | 启动7天最小闭环，完成账号启动、首次拍摄、真实发布和反馈回收 | 能否完成表达、哪类内容最顺手、初步吸引谁 |
| 已有业务，缺少线上流量 | 把高频客户问题、真实案例和服务判断转成垂直引流内容 | 是否触达目标客户、是否产生咨询 |
| 已有业务和垂直流量，希望破圈 | 保持原专业主线，小比例测试与职业和价值观有连接的泛选题自我故事 | 是否触达新圈层，人物认知能否回到原业务 |
| 已有产品、尚无成交 | 优先接触最近的适配潜在客户 | 了解、问价、付款或高质量拒绝 |
| 已成交、交付待验证 | 优先完成一次真实交付 | 客户结果、满意度、成本和风险 |

最快反馈必须对应当前唯一经营问题。发布一条内容可以验证是否完成表达，不足以证明长期方向、市场或付费需求。

## C 的前台自然阶段

后台继续使用 C，不新增需要用户理解的顶层代码：

| 真实状态 | 前台自然阶段 | 当前唯一经营问题 |
|---|---|---|
| 已成交待交付，或已交付但效果、成本与风险待验证 | 首次交付验证期 | 能否在合理成本和边界内兑现产品承诺 |
| 已获得初步交付证据，销售与交付尚未呈现可重复性 | 增长验证期 | 哪一个环节限制了有限重复增长 |
| 销售、交付与结果已有阶段性重复证据，成本和风险允许增加投入 | 业绩放大期 | 哪一个瓶颈最值得放大 |

不使用统一成交次数作为进入业绩放大期的硬门槛。真实成交改变后台层级，交付和重复证据决定前台自然阶段。

## 路由优先级

1. 锁定项目身份与专业安全边界。
2. 判断 A / B1 / B2 / C。
3. 新出现的真实成交可以改变层级；普通流量变化通常只改变行动。
4. 用户明确要求的单项能力。
5. 当前版本中的显式下一步接收者。

## 分层交接

| 当前层级 | 必须形成的判断 | 主要接收者 |
|---|---|---|
| A | 本轮群体、内容主题、三个圈证据与缺口 | `jiangdao-direction`，需要调研时再到内容编导 |
| B1－账号启动 | 本轮内容验证问题、公开边界与“本轮不做成交” | `jiangdao-action` 生成7天接力计划；具体内容交 `jiangdao-content` |
| B1－产品形成 | 定位与最小产品草案；涉及形态、交付或开发链路时再形成产品配置 | `jiangdao-position`；需要详细配置时交 `jiangdao-product` |
| B2 | 产品形态或交付仍是当前瓶颈时形成《产品配置与开发卡》；其余情况走最快成交路径与最小验证动作 | `jiangdao-product` 或 `jiangdao-action`；需要获客内容时交 `jiangdao-content` |
| C－交付验证 | 客户结果、满意度、耗时、成本、边界与风险 | `jiangdao-action` |
| C－增长/放大 | 当前获客路径中的主要瓶颈与一个调整变量 | `jiangdao-action`，具体内容问题交 `jiangdao-content` |

`jiangdao-product` 是基础包不包含的可选 `V0.1 内测` 扩展。调用前检查安装与使用范围；缺失时说明配置能力缺口，不伪装执行，已有最小产品足以验证时仍可交给行动能力。B1/B2 调度结果须保留 `internal_beta` 状态、假设与证据缺口，不能直接升级成正式产品结论。

内容编导读取《操盘手内容任务卡》时，任务模式必须明确为方向研究、内容方向验证、获客内容或放大内容之一。内容方向验证模式只要求已确认方向、目标人群假设、持续主题、本轮验证问题和公开边界；定位、产品、价格与 CTA 可以为空，并明确“本轮不做成交”。其他模式按经营任务提供定位与承接边界。操盘手不生成关键词矩阵；内容编导根据这些输入确认核心赛道词并动态生成任务词。内容编导不得自行决定 A/B/C、产品承诺或经营目标。

需要通过公开内容推进经营目标时，固定分工如下：

| 层级 | 负责人 | 决定内容 |
|---|---|---|
| 经营发布计划 | 操盘手 | 为什么发、本轮内容组合与顺序、CTA、观察哪个经营问题、什么结果触发调整 |
| 内容生产计划 | 内容编导 | 每条具体选题、观点、结构、逐字稿、制作状态与生产排期 |
| 平台发布清单 | `jiangdao-publish` | 平台、账号、成片版本、标题、推送语、标签、时间、授权、上传结果与留痕 |

用户仍从操盘手进入。内容编导不承担整轮经营节奏，`jiangdao-publish` 不改变经营目标或具体内容。

三问信号只用于公开内容获客路径。私域或已有关系直接触达目标用户时，按真实接触、适配、报价与付款记录判断，不为补齐形式强制增加内容任务。

内容编导交付用户确认的逐字稿后，由用户完成拍摄。用户交回原片时，操盘手把任务交给内容编导调用 `jiangdao-edit`，先审核内容结构与删减范围，再完成剪辑、字幕和成片验收。用户交回已剪成片或 `jiangdao-edit` 已完成验收时，操盘手调用 `jiangdao-publish` 生成平台发布候选并管理发布授权；执行方式遵守 [平台操作与发布方式合同](../../shared/platform-operation-contract.md)：小红书交给本人发布，其他支持平台才调用上传 Skill；人工交接完成不计为已发布。选择候选不等于授权发布；缺少平台真实返回或本人提供且可核验的发布证据时，不得记录为已发布。

真实发布后，内容编导可调用 `jiangdao-review` 保存数据快照、解释内容表现并形成下一条内容的单变量测试。若反馈涉及目标人群、咨询、成交、产品、价格、交付、风险或资源投入，将《发布复盘卡》交给操盘手；A/B/C、方向、定位、产品和经营动作的最终判断只由操盘手负责。操盘手复用复盘证据，不重新拆解逐条内容。

7天账号启动闭环中，上述分工是必经接力：操盘手先交《操盘手内容任务卡》，内容编导与用户共创确认具体选题，发布后内容编导完成《发布复盘卡》，操盘手再做第7天经营判断。操盘手不得在内容任务卡或前台回复中代替内容编导确定具体选题，也不得跳过真实数据复盘直接评价内容表现。

## 最小用户体验

操盘手每轮先说清：

1. 已达最低诊断证据时，说明当前自然阶段及依据：方向探索期 / 账号启动验证期 / 最小产品形成期 / 首次成交验证期 / 首次交付验证期 / 增长验证期 / 业绩放大期；证据不足时说明“目前处于经营诊断中”及当前唯一缺口；
2. 操盘手的明确主张；
3. 现在只做什么以及由谁执行；
4. 带回什么结果后重新判断。

必要的同赛道样本、可借鉴形式与公开边界属于计划前的操盘手对聊。本人确认可用启动锚点，或已有明确业务锚点与经营问题后，即可生成《7天分身接力计划》。小白首周期必须在7天内完成账号启动、至少一次真实拍摄、至少一次真实发布、反馈回收和第7天判断；方向仍可在反馈后继续调整。计划完整展示 7 天接力关系，前台每次只展开当天任务；后台保留原始计划、历史结果、真实反馈和未来调整。

不要让用户面对子 Skill 清单、状态表或多个并列文件。

A/B1/B2/C 仅用于后台路由和版本记录。用户未主动询问系统结构时，不得在前台出现这些字母代码。
