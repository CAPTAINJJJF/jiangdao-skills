# 江导内容生产

版本：V1.0.2

## 启动与独立使用

- 启动语：“启动内容生产”；“帮我写口播稿”。也可明确调用 `$jiangdao-produce`。
- 高保真改写带一篇指定完整原稿；混合二创带选题、主来源和独立补充输入；灵魂创作带本人事件、观点、口述或笔记。缺模式、观点或生产决策时在本任务补齐，具体资料资格继续执行生产资料门。
- 独立启动和分身接力的范围遵守 [入口与使用目录](../shared/skill-entry-guide.md#独立启动与接力规则)。

把用户已确认的“选题＋内容框架”生产为可拍摄内容。完整逐字稿从本阶段开始生成。

## 执行前读取

选择生产模式后，先完整读取 [单条内容生产资料门](references/production-input-gate.md)，再读取 [production-workflows.md](references/production-workflows.md) 中对应模式的完整规则，并完整读取共享的 [内容编导前台文本格式合同](../shared/content-frontstage-format-contract.md)（按合同“读取范围”加载公共规则与第九、十节）、[内容框架识别、选择与执行合同](../shared/content-framework-contract.md) 和 [内容机制卡词典](../shared/content-framework-mechanism-cards.md)；涉及初稿检查、口吻或转化时，同时读取生产工作流中的共用规则与待验证边界。《生产决策卡》和《可拍摄逐字稿》的用户可见格式只以共享前台格式合同为真源。

## 模式判断

每轮内容生产只使用一种模式：

- 高保真改写；
- 混合二创；
- 灵魂创作（兼容旧称“灵感创作”）。

用户在本轮已经明确说出模式时，直接使用；用户未指定时，由当前生产能力或上游在《生产决策卡》中推荐并随整卡确认。上一轮模式、AI 猜测或素材相似度不能代替本轮选择。

用户明确要求“把这一条高保真改写”，且来源、选题、观点、机制和公开边界都可从原稿确定时，这句话已经同时给出来源与模式，可以直接建立后台火点锁定单并交付，不额外要求用户确认抽象方案。只有改动会改变核心、立场或模式时才暂停。

## 输入闸门

开始前生成 `生产资料审计.json`，并运行：

```bash
python scripts/validate-production-input.py <生产资料审计.json>
```

固定确认：生产模式、当前选题、每份材料的全文与来源状态、材料在本稿中的功能、本人原始内容状态和《生产决策卡》状态。只有输出 `PRODUCTION_INPUT_OK` 才开稿；该结果仅表示资料资格与结构通过，稿件中的事实、归属和因果仍须对照来源核验。赛道采集批次的 20/10 条目标用于研究和数据库，不在这里重复检查。

灵魂创作额外确认：

- 用户已经通过口述、Live 对话、问答、笔记、原始稿或真实事件产生本条核心内容；
- 原始内容中至少能提取一个具体事件/问题和一个用户认可的判断；
- 用户没有产生核心内容时，先由当前生产能力或内容编导提出具体问题并继续引导，不生成完整逐字稿。

用户明确要求对单条爆款做高保真改写时，可以按单条输入执行；该任务属于单条内容处理，不能记录为内容编导从 0→1 生成新选题。

除满足单条明确高保真快速执行条件外，其他生产任务缺少已确认的《生产决策卡》时，先按模式预检材料；直接启动由本 Skill 按现有合同装配并取得整卡确认，分身接力则复用上游决策。已有选题不重新走选题共创。混合二创只有内容池时，先从已完成拆解的样本中归并合格赛道问题并写入赛道问题池，再由 `jiangdao-adapt-topic` 读取问题池、加工候选并取得用户选择；选题选中后由内容编导总入口按模式预检材料，材料齐备后形成并确认《生产决策卡》，最终资料校验通过后返回本 Skill 生成完整初稿。若用户已经确认选题，不得另换主题。

## 三种生产模式

1. **高保真改写**：完整保留原稿的信息、逻辑、功能性细节、力度和推进顺序；只承担举例作用的细节可以按生产工作流做同功能替换，其余只调整表达方式、IP口吻以及无法直接沿用的身份、商业和风险内容；具体执行只以 [production-workflows.md](references/production-workflows.md) 的“高保真改写”为真源。
2. **混合二创**：以一条主来源或一个主火点为锚，围绕已经确认的选题、观点答案与主机制确定唯一核心；辅助来源各自只补一个证据、场景、反例、方法、边界或故事缺口，重新组织成一条不能与任一源稿逐段对应的新内容。
3. **灵魂创作**：爆款文本库提供市场问题、传播机制和表达参照；用户通过引导产生观点、故事、经历、原话和立场；AI只负责提问、追问、提取、排序、结构化和高保真整理。旧任务中的“灵感创作”按本模式兼容执行。

百分比只用于理解原爆款保留程度，不向用户计算或展示精确比例。

## 未指定模式时的推荐

只有用户尚未指定模式时，才根据现有材料与用户目标推荐一种模式并给出简短理由；普通流程随生产决策整卡确认一次，用户已明确的选择不重复问。用户已经明确模式时跳过本节。

推荐时至少说明：

- 建议采用哪种模式；
- 原爆款准备保留什么；
- 人格数据库或其他素材准备补什么；
- 当前还缺什么。

用户改选后，按新模式重新组织任务，不沿用上一模式的隐含规则。

## 共用生产原则

- 先识别并保护爆款的有效部分：开头、核心问题、核心情绪、与用户强相关的主旨、鲜明观点或立场。
- 优先执行《生产决策卡》中已经采用的主要传播判断；不要把它改写成“数据已经证明该机制导致爆款”。只有与当前IP已确认立场冲突时，才应调整、换样本或切换模式。
- 不用AI自己的价值判断把鲜明观点改成模棱两可的“两边都对”或堆叠条件句；不要因观点绝对、武断或有争议就削弱核心表达锐度，也不要自动补入“可能、也许、因人而异”。缺少研究支持时保留观点，只删除或改正“研究已证明、权威认为、数据表明”等无来源背书，不得把核心结论一起磨掉。只有与当前IP确认立场冲突，或涉及虚构来源、伪造事实及明确专业风险时才调整。
- 区分并内部标记：原爆款正文、其他爆款、评论原话、人格数据库事实、用户现场补充、AI新生成内容。
- 不把AI生成或外部借鉴的经历、成绩和案例写入人格数据库，也不把它们自动标成IP真实经历。
- 原爆款故事可以从人格数据库中匹配相似经历；高保真改写匹配不到时不追问用户，改为有明确归属的第三人称材料或中性场景，并在后台标记来源状态。混合二创缺少关键本人素材时再向用户追问；灵魂创作缺少用户原始内容时必须停在引导阶段。
- 内容形式不强制使用故事。观点拆解、方法合集、清单、案例分析等都可以承接同一选题。
- 评论区是生产原料之一；加入程度决定它是辅助判断还是已经改变内容组成。
- 混合二创没有本人故事时，不要为了完整感强行追问或虚构；先判断观点拆解、方法组合、阶段规划或案例分析能否成立。只有稿件必须依赖本人事实、成绩或关键经历时再询问用户。
- 原作含亲子交流、多人对话、采访问答、情景演绎或关键画面时，读取拆解中的唯一“形式处理”结论，并按《生产决策卡》的“本次拍法”输出对应脚本。不得默认压成单人对镜口播。

## 生产顺序

1. 核对当前版《生产决策卡》已经整体确认；明确的单条高保真指令满足快速执行条件时改为核对后台火点锁定单。
2. 生成并校验当前 `生产资料审计.json`。资料不足时只补本模式缺少的输入；只有内容池且尚未定题时先把合格赛道问题写入赛道问题池，再调用 `jiangdao-adapt-topic`。高保真改写不得因为人格素材不足而暂停。
3. 按所选模式执行：
   - 高保真改写：按生产工作流中的四条核心规则执行；
   - 混合二创：围绕已确认选题与观点框架，从全部样本选择最能服务本题的唯一核心；重新生成开头与推进路线，再让不同来源分别承担问题、情绪、论据、方法、案例或收束功能；
   - 灵魂创作：先核对并复用用户已有原始内容和已确认核心判断；只针对真实缺口引导，不重新访谈已充分表达的内容。材料与决策齐备后整理成稿，市场样本按资料门辅助校准；不得由 AI 自行补出核心。
4. 生成完整初稿。
5. 先检查开头是否抓人、稿件解决什么问题，再检查转化价值与转化暗线。
6. 用户认为“不像本人”时，先调整表达口吻；若口吻调整后仍不成立，标记为生产工作流问题，不用局部润色掩盖。
7. 用户确认稿件后，交回可拍摄逐字稿；等待用户完成拍摄。用户交回原片后，由内容编导调用 `jiangdao-edit`，先审核结构与删减范围，再完成剪辑、字幕和成片验收；最终成片、逐字稿和字幕自动交回操盘手分身，由操盘手调用 `jiangdao-publish`。

## 用户表达学习

优先读取两类语言样本：

- 用户确认具有代表性的历史内容；
- 用户在 Live 或日常沟通中的自然表达。

学习其常用句式、节奏、判断方式和表达习惯，但不要机械堆叠口头禅。口吻适配不得破坏原稿的开头、核心、情绪线和推进节奏。

清理高频AI句式，尤其不要反复使用“这不是……而是……”“不是……是……”制造假反转。优先直接给出判断，或通过场景、因果和前后结果自然呈现对比。

## 前台协作

- 《生产决策卡》和《可拍摄逐字稿》严格使用共享前台格式合同；字段缺失时保留字段并写明 `不可得`、`待核实` 或 `不适用`，不得临时增删栏目。
- 生产模式已经随上游《生产决策卡》确认，本阶段不重复开启模式问答。
- 混合二创缺少故事、关键事实时，提出具体场景问题，不问空泛定义；灵魂创作只在用户核心内容或关键事实尚缺时，从具体问题引导补齐，已有材料与确认直接复用；高保真改写不因此追问。
- 用户只要求写稿且未指定模式时，不展示后台全部分析；先给模式建议和缺口，再进入生产。已指定模式时直接处理输入缺口。
- 用户只交付完整内容池时，内容编导先完成拆解与赛道问题归并，再由选题共创从赛道问题池生成并推荐候选；用户选择题目后，对《生产决策卡》做一次整体确认，不能用用户审核初稿代替上游决策。
- 不自动恢复旧版12项《内容任务书》、固定3个标题、固定3个开头或《待发布素材包》。

## 完成与退回

当前最低完成结果是：用户确认的完整逐字稿，以及仍需核验的事实或故事清单。拍摄由用户执行；原片交回后的剪辑、字幕与成片验收由 `jiangdao-edit` 承接，成片验收后自动交回操盘手分身，最终标题、推送语、标签与上传由操盘手调用 `jiangdao-publish` 承接。

出现以下情况时退回上游或暂停：

- 高保真或灵魂创作的选题、核心问题本身不成立：退回 `jiangdao-adapt-topic`；
- 混合二创只有内容池、尚未确认选题与框架：先检查能否归并出合格赛道问题；可以时写入赛道问题池并退回 `jiangdao-adapt-topic`，无法形成合格问题时返回拆解与数据库补充；
- 原爆款核心与当前IP立场冲突：换样本、换模式或交用户决定；
- 混合二创缺少必须由IP本人提供的经历或成绩：向用户追问，不由AI补成事实；灵魂创作缺少用户产生的核心内容：继续引导或暂停生产；
- 高保真改写缺少本人对应故事：继续执行，但只使用明确归属的第三人称材料或中性场景，不得写成本人经历或写入人格数据库；
- 调整口吻后仍明显“不像本人”：标记生产工作流待排查。

“可拍摄”的完整验收标准仍待用真实拍摄验证。用户交回原片后，`jiangdao-edit` 负责剪辑审核、粗剪、剪后字幕和成片验收；成片验收后自动交回操盘手分身，标题、推送语、标签和上传由操盘手调用 `jiangdao-publish` 承接。
