# 江导IP选题共创

版本：V1.0.2

## 启动与独立使用

- 启动语：“启动选题共创”；“沿这篇内容继续做选题”。也可明确调用 `$jiangdao-adapt-topic`。
- 已有赛道问题池和本轮目标；或明确指定沿一篇完整内容继续。直接启动时由本 Skill 读取并执行下述题源模式规则；缺问题池时衔接拆解或内容编导的必要研究。当前用户请求可形成内容任务快照，不要求先生成操盘手任务卡。
- 独立启动和分身接力的范围遵守 [入口与使用目录](../shared/skill-entry-guide.md#独立启动与接力规则)。

选题从当前赛道问题池中的完整问题句生长。先保留原问题的核心需求，再按规则进行迁移、具体化或损益显化；不从其他数据库栏目拼装题源。

## 执行前读取

完整读取 [topic-candidate-contract.md](references/topic-candidate-contract.md)、[选题加工规则](references/topic-processing-rules.md)和共享的 [内容编导前台文本格式合同](../shared/content-frontstage-format-contract.md)（按合同“读取范围”加载公共规则与第八节；进入生产决策时补第九节）。用户选中选题、准备形成生产决策时，再读取当前 IP 的可用材料、共享的 [内容框架识别、选择与执行合同](../shared/content-framework-contract.md) 和 [内容机制卡词典](../shared/content-framework-mechanism-cards.md)。候选判断和证据边界以选题合同为真源；问题加工方式以选题加工规则为真源；所有用户可见格式只以共享前台格式合同为真源。

进入批量候选生成前必须完成选题前置审计和本轮口味校准。缺少硬输入时停止并返回唯一缺口；缺少可用校准时进入“两条一轮”的共创校准，不先生成 10 条“参考候选”。交付正式候选清单时，在任务资料包生成后台 `选题候选审计.json`；它逐条保存正式题源、加工路径、损益、目标受众、内容承载力、共鸣范围和观点状态。审计信息不进入前台。校准阶段按选题合同用普通对话并保留题源、规则和用户反馈；正式候选文件生成后必须运行：

```bash
python scripts/validate-topic-candidates.py <选题候选清单.md> \
  --audit <选题候选审计.json> \
  --problem-pool <当前单赛道/赛道汇总库.json> \
  --mode <single_source|track_pool>
```

只有正式问题池精确匹配、后台语义审计和前台结构同时通过并输出 `VALIDATION_OK`，才能把候选交给用户。数量覆盖只能来自用户在当前任务中的明确要求；助手先前提出的建议、旧任务状态和内部下一步不能作为覆盖依据。

## 唯一题源

- 已确认的当前项目、当前赛道和当前内容任务；
- 当前赛道数据库“赛道问题池”中的完整问题句；
- 每个问题在后台保留的来源索引与证据状态，只用于追溯和排除错误归属，不参与扩写题意；
- 当前 IP 身份只用于防止把原作者或第三方的身份、经历和成绩迁移给当前 IP。候选阶段不读取人格数据库改题。

其他数据库栏目不作为本阶段题源。用户从单条爆款提出改题需求时，先完成拆解并把合格的赛道问题写入赛道问题池，再进入本 Skill。

## 两种题源模式

- **单篇题源共创 `single_source`**：只在用户明确要求沿当前文章继续做选题时使用。后台锁定一个赛道问题 ID 和该篇来源记录；所有候选只能从这个问题生长。前台在清单标题下显示单篇范围提示，不将候选描述为赛道共识、市场验证或稳定规律。
- **赛道问题池共创 `track_pool`**：用于常规选题、赛道选题和经营任务。后台锁定本轮允许使用的问题 ID；至少需要两个合格问题，或一个由两个独立样本共同支撑的合并问题。题源不足时停止并返回补充研究，不自动切换到单篇模式。

两种模式都只读取赛道问题池。由内容编导调度时复用已确定模式；直接启动时按用户请求和本节规则确定模式，并作为校验命令的显式参数。题源不足不得自行改换模式。

## 决策顺序

1. 锁定当前项目、当前赛道、正式赛道数据库、当前内容任务、IP 身份和题源模式。
2. 读取已有内容任务；直接启动时将用户本轮目标、人群、主题与边界保存为当前任务快照，已有事实不重复补问。经营变量仅在本轮确有经营测试时锁定；与当前任务无关的候选不进入凑数。
3. 检查当前项目、IP、赛道和目标人群范围内有没有用户亲自判过的正反样本与理由。只有模板、旧爆款和 AI 自评时，视为尚未校准。
4. 尚未校准时，每轮只测试一条加工规则并生成两条候选。用户选择一条、认可两条或全部 Pass，并说明原因；一次只改一个变量。某条规则在不同母题上重复成立，并且用户同意进入批量生成后，才把它写入本轮校准依据。
5. 只读取赛道问题池中的完整问题句；单篇模式锁定唯一问题，赛道模式筛出与当前任务相关的允许问题。
6. 对入选问题先寻找目标客户真实在意的损益，再尝试现场处理、前兆诊断、信号归并、关系反差等发展路径，最后按目标受众、共鸣范围、内容承载力、表达空间和实质差异择优。
7. 按共享格式合同生成并校验《选题候选清单》；用户选中后交回内容编导总入口按生产模式预检材料，材料齐备后再按选题合同确认一张《生产决策卡》，通过最终资料校验后交给 `jiangdao-produce`。

校验失败时只淘汰或重做具体失败项。题源不存在、核心需求偏移、新增元素无直接依据、题面提前写答案、身份成绩归属不明或候选近义重复，均不得通过改写“建议”字段掩盖。

## 问题加工

元素迁移、选题具体化和损益显化继续作为底层加工动作。候选还要记录它怎样长成一个完整问题：现场处理、前兆诊断、信号归并、关系反差或其他经用户校准的路径。每条候选都要显示保留了哪个赛道问题、采用了什么加工动作以及发生了什么具体变化。

损益是候选排序的主轴。题面要让目标客户感到继续忽略会损失什么，或看完能够解决什么；泛泛的“警惕”“风险”“价值”不算损益。损益需要落到目标客户会亲自承担的麻烦、失控、错判、关系恶化、时间成本或机会损失上。

一条完整选题需要能够自然展开出多个信号、原因、判断或处理动作。单个反常表现只够成为正文素材时，把它留在素材层，继续向上归并成更大的诊断问题。

## 不可违反

- 固定区分：`赛道问题 -> 选题加工 -> 选题 -> 观点与内容答案 -> 标题/钩子`。选题允许两种状态：答案开放的问题；带方向性判断、等待用户认领的候选命题。后台必须标明状态，任何 AI 候选都不能静默写成用户既有观点。
- 第一句使用目标客户一遍就能理解的自然说法。开放问题通常以问号收束；方向性命题可以用陈述句，但要保留解释和反驳空间。避免连续堆叠抽象名词，也不靠“秩序、权威、风险、行动改进”等概念词代替具体的人、动作和后果。
- 建议段允许给出候选观点方向和候选框架，但必须使用“可以考虑”“建议从”等候选语气；不得把 AI 推演写成江导本人的既有判断。
- 建议段不能只做执行说明。优先指出题目背后的隐藏冲突、容易忽略的解释、值得反驳的常见理解或与本人经历形成的反差，让用户先产生“我有话想说”；随后再给框架和推进方式。
- 启发需要基于赛道问题和当前任务，可以贡献一个新连接或可纠正判断；不得用空泛反问、宏大升华和未经证实的断言制造假深度。
- 候选阶段不生成正式标题、钩子或完整逐字稿。
- 元素迁移、选题具体化和损益显化只加工已经合格的问题；不得用加工动作补造目标用户信号、事实、因果、效果或本人经历。三条方法按需组合，不要求每条候选全部使用。
- 不规定每条必须使用两个加工动作，不规定必须写成 A/B 决策，也不把“为什么”或“三个信号”当成固定句式。加工动作只在确实改变问题价值时使用。
- 完整选题共创默认统一生成 10 条；用户明确要求其他数量、只改一个具体题或只看某一类时，只覆盖当前任务。前台保持连续编号，不显示题源分组。
- 作者脚本、剧情对白、角色扮演、AI 演绎和未经证实的案例台词不能冒充目标用户原话。它们只可提供场景、表达或形式机制；除非来源明确记录真实用户发生过的对话，并保留证据状态。
- 其他赛道问题不能混入当前赛道；行业迁移只借问题结构，新赛道元素仍要在当前问题语义和任务边界内成立。
- 全新赛道选题不能与来源原选题同义，不能只替换对象、学段、数字或情绪词；至少在讨论对象、触发场景、待解释现象或用户决策中的一项发生实质变化。
- 增加条件前先检查共鸣覆盖率。会议、提拔、批评、复盘等高频现场可以增强代入；只有少数人才会遇到的剧情条件通常退回素材层。真实存在本身不足以证明值得成为候选。
- 每条候选都要回答“谁会想点开”。主要让非目标人群获得情绪满足、同时让目标客户感到被审判的题目，标记为错受众风险并淘汰或重做。
- 单个信号、一个小反常或一句提醒不足以撑起完整内容时，不得拿来补足数量。可以把多个相关信号归并为目标客户需要自查的更大问题。
- 候选要激发创作者自然想到案例、判断、原因或做法。题目已经把结论写死，或抽象到无从开口时，都没有通过内容激发力检查。
- 候选阶段不读取人格资料改题，也不把任何外部身份、经历、粉丝量、收入、客户结果或项目成绩迁移给当前 IP。
- 一条选题不以“必须有本人故事”为成立条件；观点拆解、方法、清单、对比和案例分析都可以承载。
- 候选之间必须在对象、场景或待解释现象上有真实差异，不能靠换情绪、钩子或近义标题凑数量。
- 用户确认选题后，观点可以保持或加强锐度；不得因绝对、有争议就自动软化，但不得虚构事实、研究和专业结论。

## 前台与交接

校准阶段按选题合同使用两条一轮的普通对话，不生成正式清单；校准完成且用户同意批量生成后，首次正式交付只展示共享格式合同规定的《选题候选清单》。不得删掉题源原话、生成关系或直达来源，也不得恢复旧版“一句问题＋一段建议”的两字段格式。建议段仍需提供能激发表达的隐藏冲突、新连接或可纠正判断，并说明候选回答角度；框架名称单独出现时必须同时写清推进方式。

用户选中后，先把选题和题源状态交回内容编导总入口按模式预检材料。材料齐备后再严格按选题合同装配并确认一张《生产决策卡》，这时才读取完成内容所需的本人材料和框架资料；整卡确认后由总入口运行最终资料校验。后台保留赛道问题句、加工动作、来源索引与确认记录；用户追问来源时，直接给出对应赛道问题及其来源索引。

最终合格候选不足 10 条时如实报告问题池或加工空间不足，不用弱题凑数。

完成状态可以停在“选题已选中，待补生产材料”，也可以在材料齐备后到达“生产决策卡已确认”。用户只选中题目时，不将建议段里的候选观点或机制静默升级为已确认。本 Skill 只锁定可执行的本次拍法，不生成完整逐字稿，也不展开最终语言、镜头细节和表演设计。
