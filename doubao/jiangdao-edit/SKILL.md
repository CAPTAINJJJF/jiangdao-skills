# 江导视频剪辑

版本：V1.0.1

把真实原片变成可追溯的 A-roll、在线时间线或剪映工程。每次先把完整工作流展开给用户确认；确认后只保留一个活动路线和一份阶段状态卡。

## 执行前读取

每次完整读取 [editing-contract.md](references/editing-contract.md) 和共享的 [内容编导前台文本格式合同](../shared/content-frontstage-format-contract.md)。路线锁定为 `local_a_roll` 后，再完整读取 [local-a-roll-contract.md](references/local-a-roll-contract.md) 和 [jiangdao-transcribe](../jiangdao-transcribe/SKILL.md)。其余路线不加载本机删重、气口和审核页细则。用户可见的剪辑审核入口和成片交付字段遵守共享格式合同，不再创建第二套审核页格式。

任务目录已有 `EDITING_STATE.json` 时必须先读回并运行 `scripts/validate_editing_state.py`；没有时先从实际项目、时间线和文件建立一份。聊天中的“测试版、审核版、底轨版、正式版”不能替代状态卡中的唯一活动对象。

路线锁定为 `chatcut_edit` 后，完整读取 [chatcut-desktop-contract.md](references/chatcut-desktop-contract.md)。默认使用 ChatCut 正式版桌面应用；只有需要分享链接、云端预检/渲染、桌面版不可用或用户明确要求网页时，才锁定网页端。

锁定 `chatcut_jianying` 路线，或 `full_package` 已完成正式包装并进入剪映交接阶段时，完整读取并调用 [jiangdao-chatcut-jianying](../jiangdao-chatcut-jianying/SKILL.md)。只有用户明确要求完整自动化包装时，才读取 `chengfeng-videocut-skills:口播成片`。完整包装包含新动效时，还必须读取 [运行配置合同](../shared/runtime-configuration.md)，定位 `motion_style_library` 后读取其中的 `WORKFLOW.md` 和当前 `catalog.json`；没有有效 `motion_style_id` 时先打开选择页并等待用户确认。

本机路线使用本 Skill 的 `scripts/` 和 `jiangdao-transcribe`，不读取或调用已淘汰的外部基础剪辑入口。

凡是进入逐字稿删减、误删恢复、结构编排或正式剪点确认，必须读取并使用已安装的 `course-cut-review`（从当前已安装 Skill 入口解析路径，见 [运行配置合同](../shared/runtime-configuration.md)）。它是视频与课程统一的内容审核入口；旧版 `generate-review.js` 只用于读取历史项目，不再生成新审核页。

## 输入闸门

开始前至少确认：

- 用户有权处理且可读取的原片；
- 当前内容任务、目标平台或交付场景；
- 定稿口播的确认稿；随机访谈可以没有定稿，但须保留完整原始转写；
- 本轮已经明确的比例、倍速、字幕、包装和精修要求。

工作流确认后，仍缺少且不会改变内容结构的样式参数可以在包装前补齐。原片不得覆盖、移动或修改。

## 先展开并确认完整工作流

开始任何剪辑执行前，先按 [editing-contract.md](references/editing-contract.md) 输出一份简短《剪辑工作流确认卡》。根据素材判断 `scripted_short`、`course`、`demo`、`interview` 或 `mixed`，说明：素材角色与主声音、内容删改逻辑、画面对轨/演示逻辑、字幕与包装、工具路线与降级、阶段顺序、人工确认点、交付物和验收口径。

工作流确认前只允许查看用户要求、文件清单和基础媒体信息。不得转写、上传、建立或修改时间线、生成动效、导出或渲染。用户明确同意当前工作流后，将类型、版本、摘要与确认时间写入 `EDITING_STATE.json`，再开始执行。

后续若改变内容顺序、主声音、演示证据、工具路线、交付轨道或验收口径，先生成新的工作流版本并重新确认；不能在执行中静默改变剪辑逻辑。

## 先锁定唯一执行路线

工作流确认后、第一次上传、转写或全片分析前，在任务记录写入 `route_lock`：

| 路线 | 适用交付 | 核心动作 |
| --- | --- | --- |
| `local_a_roll` | 干净口播、SRT、审核页 | 本机转写 → 审核 → 确认后渲染 |
| `chatcut_edit` | ChatCut 可编辑初剪或直接成片 | 锁定桌面/网页端 → ChatCut 初剪 → 本机或云端导出 → 实播 |
| `chatcut_jianying` | ChatCut 初剪或已确认包装继续剪映 | 时间线双读回 → 能力预检 → 独立剪映草稿 |
| `full_package` | 已确认 A-roll 的完整包装 | 先完成 A-roll，再进入分镜、预览与导出 |

课程长视频只需 ChatCut 工程或最终成片时，优先锁定 `chatcut_edit` 并使用桌面版；明确需要剪映继续美颜、混音、字幕或包装时，才锁定 `chatcut_jianying`。`chatcut_jianying` 默认先生成低码率代理。`chatcut_edit` 桌面版先做格式与性能小样：本地原片可稳定编辑时直接使用，超大、高帧率、特殊编码或性能不稳时改用受控代理。

路线与 ChatCut 操作端锁定后，工具超时或单步失败不会自动切回本机旧流程、网页或桌面版。确需改变路线或操作端时，先说明原因、复用哪些既有产物，并把变更记为新版本；旧版本停止继续加工。

## 素材分支

- **定稿口播 / 课程**：保持原顺序。确认稿是语义基准，允许自然改写和现场补充。
- **随机访谈**：先锁定一个由素材证明的核心观点，再确认开头、内容厚度、说话人和论证闭环；结构确认前不渲染。
- **包装范围**：默认只交付 A-roll、字幕和验收。音乐、花字、MG、B-roll、美颜与画面重构需要用户明确提出。

## 主工作流

1. 读取用户要求、文件清单和基础媒体信息，判断视频类型并展开完整工作流。
2. 停在“工作流待确认”。用户确认前不转写、不上传、不建时间线、不生成或渲染。
3. 建立 `EDITING_STATE.json`，写入已确认工作流类型、版本、摘要、确认时间、交付目标和验收口径，再锁定活动路线；使用 ChatCut 时登记 `surface_lock`，只有交付成片时才锁定 `export_mode=local|cloud`，仅转工程写 `export_mode=not_applicable`。
4. 每次恢复任务与切换工具都重新读回状态卡；新参数或新工具先用 1—3 分钟代表性片段验证。
5. 按活动路线执行：
   - `local_a_roll`：调用 `jiangdao-transcribe`；生成低风险自动候选和高风险待确认项；调用 `course-cut-review` 生成唯一新版审核入口。
   - `chatcut_edit`：锁定桌面版或网页；桌面版优先使用可稳定编辑的本地原片，必要时生成保持完整声音、比例和稳定帧率的代理；先用 `course-cut-review` 确认逐字稿删减和编排，再把已确认方案应用到复制的活动时间线，按锁定操作端导出并验收本地文件。
   - `chatcut_jianying`：按子 Skill 生成代理并完成 ChatCut 初剪；用户确认活动时间线后调用 `jiangdao-chatcut-jianying` 转换，转换阶段不再二次删内容。
   - `full_package`：先完成并验收 A-roll；涉及新动效时先完成风格选择门并记录 `motion_style_id`，再把该 ID 传入完整包装能力；需要交给剪映时保持路线不漂移，推进到 `handoff_preflight` 并调用交接子 Skill。
6. 按已确认工作流进入对应确认点；涉及结构和删减时停在“结构与删减待确认”。
7. 从原片按确认版本一次渲染；先处理内容，再按已确认逻辑处理气口、演示等待、课程连续性或结构重组。
8. 进入 ChatCut 导出或剪映交接前，按路线合约完成时间线双读回、剪映安装、会员/透明动效能力和目标路径预检；首次发现限制后锁定已授权降级模式。
9. 检查片头、片尾、剪点、音画和完整性；从当前粗剪或回片重新转写并校正最终字幕。
10. 真实播放开头、中段和片尾。工程交付还要在 ChatCut 或剪映中实际打开抽查。
11. 交付同一工作流版本的成片/工程、SRT、逐字稿、状态卡、任务记录和已知限制。发布仍需单独授权。

## 节省时间和算力的硬规则

- 同一原片指纹、ASR 配置和已有结果一致时复用转写，不重复调用 ASR。
- 工作流未确认时，所有会生成或修改剪辑产物的步骤保持锁定。
- 默认只做一轮确定性扫描；整句删除、语义重叠和结构重组进入人工审核，不默认启动多角色或多 Agent 复核。
- 内容锁定前不做字幕样式、动画、完整导出或多版本渲染。
- 正式整条渲染前先完成能力与路径预检；限制首次出现后不再用相同参数重复渲染。
- 首次整条操作超时后停止同参数重试；改为分段、分页或修复连接，再从已有进度恢复。
- 长时间线分成内部工作批次读取和校验，最终仍保留一个活动版本；不得因批次处理制造多条互相漂移的时间线。
- 工具的“成功”提示只代表该步返回；真实文件、活动时间线和播放器结果才进入验收记录。
- “素材已导入、轨道已生成、字幕已落轨、草稿已保存、实际播放通过”分别记录，禁止相互代替。

## 完成标准

- 活动路线、用户确认、原片和输出版本可追溯，过程中没有静默切换路线。
- 工作流类型、版本、摘要和用户确认时间可追溯，实际执行与确认卡一致。
- `chatcut_edit` 已记录桌面/网页操作端和导出模式；桌面版交付已验证本机导出文件，网页交付已验证云端产物实际下载后的本地文件。
- `chatcut_jianying` 使用代理上传，最终剪映草稿已关联本地原片。
- `EDITING_STATE.json` 与实际项目、正式时间线、交付范围和验收版本一致。
- 所有正式删除与重组来自用户确认版本；原片未被覆盖。
- 最终字幕来自当前最终视频的重新转写和校对。
- 视频可完整解码，音画同步，片头片尾完整；工程已实际打开播放。
- 交付项与验收项属于同一版本，未把“待外部精修”写成最终完成。
