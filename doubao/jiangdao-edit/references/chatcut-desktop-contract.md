# ChatCut 桌面版路线合约

只在 `route_lock=chatcut_edit` 时读取。目标是保留 ChatCut 可编辑时间线，同时优先用桌面版完成本机导出和本地验收。

## 1. 双锁

任务记录同时保存：

- `surface_lock=desktop|web`；
- `export_mode=local|cloud`；
- ChatCut 渠道、项目 ID、活动时间线 ID；
- 导出格式、分辨率、帧率、目标路径和输出版本。

默认组合为 `desktop + local`。下列情况使用 `web + cloud`：需要分享链接、云端预检/渲染、桌面版不可用，或用户明确要求网页。使用 ChatCut Beta 必须获得用户明确同意，不把 Beta 项目状态当正式版状态。

操作端切换视为路线内版本变更。先记录原因、已有产物和恢复点，再切换；禁止因加载慢、超时或界面空白静默改用另一端。

桌面导出还需要“双读回”：

1. 通过 ChatCut MCP/Agent 读取当前工作时间线的项目 ID、时间线 ID、名称、时长和轨道摘要；
2. 在桌面应用读取当前可见并被选中的时间线，记录同一组字段；
3. 将两组结果与 `EDITING_STATE.json` 的正式时间线比较。

三者完全一致后才能开始正式导出。桌面当前可见时间线可能决定实际导出对象，MCP 返回的活动时间线不能单独作为证据。任一处只有名称、缺 ID 或结果不一致时，停在导出前并重新选择。

## 2. 桌面版能力边界

- 桌面版与网页使用相同的时间线、面板和项目，但属于独立构建。
- 桌面版导出在本机执行，支持 4K 和本地文件处理。
- 网页版保留云端渲染、云端预检和分享链接。
- 手动导出面板使用 MP4（H.264）或 WebM（VP8）。需要透明背景 ProRes 时，通过已连接的 Agent 本机导出能力执行并单独验证 alpha。
- 桌面版可在 Agent Selection 扫描本机 Codex 或 Claude Code。使用本机 Agent 时，记录所选 Agent 和项目工作区；扫描成功不代表时间线或导出已验收。

产品能力可能更新。遇到界面或格式与本合约不一致时，先查 `https://chatcut.io/docs/desktop-app` 和当前可见选项，再更新任务记录，不猜测隐藏设置。

## 3. 整条渲染前预检

先用只读探测或最短代表片段确认：

- 剪映专业版已安装，版本可读，目标草稿目录可用；
- ChatCut 当前账号/会员能否导出本轮需要的 Motion Graphics、透明背景或 alpha 格式；
- 目标输出目录存在且可写，文件名不会覆盖已有交付；
- 交付轨道白名单、目标时长、分辨率、帧率和音频范围已写入状态卡。

能力值使用 `supported`、`unsupported` 或具体受限原因，不能在正式渲染前保留 `unknown`。透明 Motion Graphics 能力受限时，立即锁定已授权的 `clean_base_overlay_srt` 模式；若用户尚未授权降级，停在预检并说明影响。首次限制已经提供足够证据，后续不再用整条视频重复测试同一能力。

## 4. 素材策略

1. 原片保持只读，先探测 codec、profile、pix_fmt、分辨率、帧率和时长。
2. 用 1—3 分钟代表性片段验证桌面版播放、拖动、转写和切点响应。
3. 本地原片稳定时直接使用；超大、高帧率、特殊编码、外置盘吞吐不足或时间线明显卡顿时生成受控代理。
4. 代理保持完整声音、比例、方向和稳定帧率，并保存与原片的映射。代理仅用于工作时间线，不自动成为最终成片来源。
5. 不因桌面版存在而跳过内容结构确认、字幕校对或片头片尾检查。

## 5. 工作流

```text
原片只读与媒体探测
→ 锁定 desktop/local 或 web/cloud
→ 代表片段验证
→ 导入本地原片或受控代理
→ 按原始时间完成多源对轨，并应用开工时用户选定的提前倍速（明确不加速则为1倍）
→ 转写与冗余/重复预删
→ 用户首次审核已默认划线的结构/删减方案
→ 同一活动时间线完成 A-roll
→ 字幕与一次音频精修
→ MCP/桌面可见时间线双读回
→ 能力与输出路径预检
→ 按锁定模式导出
→ 本地文件验收
```

内容确认前不做完整导出、字幕样式、动画或多版本渲染。ChatCut 出现 99% 转写、空 Viewer 或同步中断时，先检查文字稿、轨道、波形、项目和实际播放；保留进度后再恢复连接或重转，禁止先重传原片。

## 6. 本机导出

1. 明确导出范围、格式、分辨率、帧率和输出目录。
2. 导出到当前任务的独立 `delivery/` 或用户指定目录，不覆盖旧成片。
3. 等待文件大小稳定后再验收；界面“完成”只代表导出步骤返回。
4. 从本次导出的文件重新生成或核对最终字幕，确保字幕与交付成片同版本。
5. 导出失败时保存错误、目标路径和时间线版本；修复原因后重试当前版本，不从头重建项目。

导出只读取交付白名单。隐藏、静音或关闭可见性的轨道仍属于当前项目结构，不能据此推断它不会被导出或转换。需要干净底轨或独立覆盖轨时，新建只包含对应交付轨的干净项目，并在新项目中再次核对轨道数、00 点、总时长和首尾。

网页云端导出仍须等待云端完成、下载到本地并核对实际字节数。大文件使用单文件下载或断点续传，禁止把云端状态直接写成已交付。

## 7. 验收

至少完成：

- 文件存在、大小大于零且已稳定；
- `ffprobe` 核对时长、分辨率、帧率、视频编码和音频编码；
- 全片可解码，音视频时长差异在可解释范围；
- 实际播放开头、中段、关键剪点、字幕密集段和片尾；
- 音画同步，片头未误切，片尾包含最后一句和必要动作余量；
- 4K 交付确认为 3840×2160 或任务指定的等效竖屏尺寸；
- 透明 ProRes 额外检查像素格式、alpha 通道及前中后代表帧；
- 项目、活动时间线、导出文件、字幕和验收记录属于同一版本。

完成后交付本地成片绝对路径、SRT、无时间码逐字稿、任务记录和已知限制。若后续还需剪映精修，改锁 `chatcut_jianying` 新版本并保留当前桌面导出作为审核参考，不能用扁平成片替代可编辑时间线清单。
