# 内容生产工作流 V0.2

> 前置条件：标准生产任务已经按选题合同完成并确认《生产决策卡》；单条来源与高保真改写指令已经明确时，由后台火点锁定单替代。每轮只使用一种生产模式，不沿用上一轮模式代替本轮判断。

## 目录

1. 高保真改写
2. 混合二创
3. 灵魂创作
4. 评论区素材
5. 初稿检查与转化
6. 已确认与待验证边界

## 0. 共用语料门

开稿资格统一读取 [单条内容生产资料门](production-input-gate.md)，并以 `validate-production-input.py` 的结果为准。赛道采集批次目标继续用于研究和数据库更新，不决定每条稿件是否开工。

- 高保真改写读取一篇指定完整原稿；
- 混合二创读取一篇主来源和至少一份独立补充输入；
- 灵魂创作读取用户产生的具体起点和已确认核心判断；市场样本缺失时标记未做市场校准；
- 所有外部生产材料保留来源与全文状态，未达到正式市场样本门槛时不声称市场验证。

## 0.1 框架执行门

- 生产输入必须包含已经确认的主机制卡和内容推进链；只有框架大类名称时退回补齐具体机制与推进链。
- 先把推进链转换成段落功能，再为每一段指定爆款正文、评论、本人材料、案例或数据来源。
- 框架控制内容顺序，不能代替内容原料。关键段落缺少真实材料时，补材料、删掉该段或更换框架。
- 原作框架只在用户确认借用时沿用；选题被借用不代表框架自动继承。
- 初稿验收时逐段检查是否完成推进功能，避免把框架写成标题标签后继续自由拼接。

## 0.2 条件触发：形式处理

《生产决策卡》固定显示“本次拍法”。纯单人口播填写“单人对镜”，不增加单独确认；来源内容含亲子交流、多人对话、采访问答、情景演绎、画外音配画面，或关键价值依赖动作与关系时，读取拆解中的唯一 `形式处理` 状态并填写对应拍法。

- **直接使用**：可以生成单人对镜稿；提问者或画面只作为自然入口，不虚构新的互动。
- **转译形式**：把原关系和现场转成第一人称复盘、故事讲述或场景演练。关系位置、关键问答和动作结果要有对应承载，不能只合并双方台词。
- **保留原形式**：生成双人对话、情景脚本或画外音与画面脚本；当前 IP 缺少必要角色、场景或素材时，只借选题或机制，不强行生成普通口播。

呈现形式与三种生产模式是两个维度。高保真原则上同时保留原内容机制和呈现关系；把关键对话或关系大幅转成单人叙述时，按形式转译后的混合二创执行。最终交付必须与“本次拍法”一致：单人稿只写一个可直接说的角色，双人稿保留角色轮次，情景稿保留必要动作，画面稿标出承载关键信息的画面。除必要拍摄资源缺失或方案发生实质变化外，不增加新的确认轮次。

## 1. 高保真改写

### 定义

高保真改写完整保留原稿的信息、逻辑、功能性细节、力度和推进顺序；只承担举例作用的细节可以按下方核心规则做同功能替换，其余只调整表达方式、IP口吻以及无法直接沿用的身份、商业和风险内容。它不以缩短、摘要或变得更整齐为目标。

### 四条核心规则

1. **完整拆解**：读完全文，逐段识别观点、解释、用户心理、冲突、具体动作、例子、结果、题面承诺和承上启下关系；同时记录每个信息点的功能，不用一个抽象标签代替多个信息点。
2. **默认保留**：原稿中有功能的信息点默认全部进入新稿。合并或删除前必须在后台记录理由；说不出理由时保留。
3. **只换表达**：可以调整句式、口语节奏、连接词、称呼和IP习惯用词；原稿的信息量、论证过程、具体细节、情绪力度和推进顺序保持对应。允许信息点和段落功能逐项对应，禁止只做同义词替换。具体细节默认保留；只承担举例作用、不参与证据、转折或核心机制的细节，可以根据目标用户和IP语境做同功能替换。替换后必须同样具体，并保持原来的逻辑类别、表达力度和信息密度。
4. **逐项回查**：成稿与原稿逐项对照，检查信息遗漏、具体内容抽象化、锐利表达软化以及新观点或新事实混入。原稿更具体、更有力度或更有获得感时，恢复对应信息后再交付。

### 允许删除的四种情况

- 明确的商业植入；
- 未经核验的数据、医学或其他专业结论；
- 当前IP无法冒充的个人经历、身份和成绩；
- 确实没有新增信息、情绪或推进作用的重复表达。

删除后仍要保留该段原本承担的必要功能；个人经历可改为有明确归属的第三人称材料或中性场景，不得写成IP本人真实经历。

### 模式边界

用户明确要求对指定原稿高保真改写后，除非源稿缺失到无法处理，否则直接交付，不设素材补访闸门。大量改变开头功能、内容内核、主要顺序或加入新素材时，切换为混合二创。评论区在高保真中只用于理解用户和检查表达；其内容大量进入正文时同样切换为混合二创。

## 2. 混合二创

### 目标

围绕已经确认的选题、观点答案与主机制卡，确定一条主线和一个主来源或主火点，重新生成开头和推进路线，再让少量辅助来源补齐主线真正缺少的部分。成稿需要成为新的完整内容，避免多篇素材平均分配造成平庸。

### 素材来源

- 一条主爆款（可选）；
- 一个由多条爆款组成的内容池；
- 其他同类爆款；
- 各样本评论区；
- 当前IP人格数据库；
- 用户现场补充；
- AI为衔接与表达生成的候选内容。

### 两种起点

**主爆款起点**

- 已有一条开头、问题、情绪或主旨特别强的爆款时，把它作为锚点；
- 只保护《生产决策卡》中已经确认要借、且与当前IP立场不冲突的火点与机制；
- 允许重做框架并大量加入其他来源。一旦整体结构和内容组成被重做，按混合二创执行，不再套用高保真边界。

**内容池起点**

- 用户交来多条同赛道爆款或一个文本集时，生产前必须选出一条主来源或一个主火点；
- 先从已完成拆解的样本中归并答案开放的赛道问题，并写入当前赛道问题池；
- 调用 `jiangdao-adapt-topic` 只读取赛道问题池，按三条加工规则展示候选并等待用户选择，再按选题合同完成并确认《生产决策卡》；
- 两次人工决策完成后围绕已确认内容确定唯一核心并生成稿件；用户已经确认选题时不得另换主题。

### 内容池混合二创步骤

1. **归并赛道问题**：从全部已拆解样本提取赛道问题，完成语义合并、来源关联和答案开放检查后写入赛道问题池；情绪、观点、方法、场景、框架和原话继续留在研究资产中。
2. **加工候选**：由 `jiangdao-adapt-topic` 只读取赛道问题池，使用元素迁移、选题具体化和损益显化生成候选并推荐一个优先项。
3. **完成上游确认**：取得用户的选题选择，再生成一张《生产决策卡》并取得整体确认。未完成时停止，不生成局部或完整稿件。
4. **确定主来源与唯一核心**：围绕已经确认的选题、观点答案与主机制，选择一条主来源或一个主火点，以及服务目标用户的一个唯一核心。
5. **重新生成开头**：围绕已确认核心另写钩子。除用户明确要求保留外，不默认套用某一源稿的原开头。
6. **重搭推进路线**：在已确认框架内决定内容怎样提出问题、展开原因、给出判断、提供方法并完成收束，再安排素材。禁止先复制一篇源稿的段落顺序再往里塞材料。
7. **给辅助来源分配唯一功能**：每个辅助来源只补一个明确缺口，如证据、场景、反例、方法、边界或本人故事。不能让主线更深、更锋利或更可信的素材直接删除；建议控制为一条主来源加 1—3 条有效辅助来源。
8. **统一推导与口吻**：用当前IP的判断方式把材料连成一条因果主线，补齐必要的解释与过渡，清除来源之间的语言跳跃。
9. **完成删减检查**：逐段问“删掉后主线是否变弱”。删掉也不影响核心、厚度或可信度的段落立即删除；不得为了显示引用了多条爆款而保留。
10. **完成独立性检查**：比较每一篇主要源稿。若成稿仍能与其中一篇在开头、框架、段落顺序和主要内容上大面积一一对应，说明混合不足，应回到第4至第6步重新生成。
11. **交付说明**：正文前只需说明本稿选择的唯一核心；正文后简短列出主来源与辅助来源各自贡献了什么，帮助用户判断是否真正完成混合，不展示冗长后台分析。

### 核心选择方法

选题确认前，先把跨样本反复出现且答案开放的问题归并进赛道问题池，再由选题共创完成加工。选题确认后，围绕用户确认的观点答案确定唯一核心。历史内容池的具体案例和结论只在生产决策阶段按需调用。

### 框架重组要求

混合二创至少应出现以下三项实质变化：

- 唯一核心由跨样本关系重新提炼，或由用户重新指定；
- 开头围绕新核心重新生成；
- 内容推进顺序与任何一条单独源稿明显不同；
- 至少两个来源承担不同内容功能；
- 结尾回到新核心完成收束，而不是沿用主爆款原结尾。

只改口吻、替换案例、加入一两段其他素材，整体仍沿着原稿展开，属于高保真改写，不得标记为混合二创。

### 不需要强行加入的内容

- 不要求每条稿件都出现本人故事；
- 不要求把内容池中的每一条素材都用上；
- 不要求同时保留问题、情绪、观点、方法和故事的全部类型；
- 不因缺少故事而暂停，可改用观点拆解、阶段规划、方法组合、清单或案例分析；
- 只有稿件依赖IP本人的经历、身份、成绩或结果才能成立时，才向用户追问并核验。

### 冲突处理

- 当前IP仅仅“不习惯”某种表达，不足以推翻《生产决策卡》中已经采用的主要传播判断。
- 当前IP确认的立场与主爆款冲突时，不强行保留；交用户决定调整立场表达、换主爆款或切换灵魂创作（旧称“灵感创作”）。
- 多个样本互相冲突时，优先服从本稿唯一核心与当前IP确认立场；无法判断时保留冲突并交用户选择，不把互相矛盾的观点同时塞进正文。
- AI不得自行把鲜明立场软化为中立表述。

### 从高保真切换到混合二创的信号

- 改动原开头、核心或关键金句；
- 重做主要框架；
- 加入多条爆款的大量内容；
- 评论区素材改变了正文组成；
- 新故事、新观点或新方法成为主要内容。

### 混合二创验收

- 能用一句话说清整稿的唯一核心；
- 开头直接服务该核心，并具有独立抓力；
- 每一段都能说明自己在主线中的作用；
- 多个来源被重新组织，而非依次摘要或机械拼接；
- 有一条明确主来源或主火点，辅助来源各自只承担一个不可替代的功能；
- 形式转译时，原作关系、关键问答或现场张力在新拍法中有明确承载，没有被压成平铺的单人口播；
- 没有因为多来源自动写成平均用力的“三点、五步”清单；
- 至少两个来源提供了不同功能的有效材料；
- 去掉素材来源标签后，语言、推导和节奏仍然统一；
- 成稿无法与任一源稿大面积逐段对应；
- 没有为了“像本人”虚构IP经历、成绩和事实；
- 清理了高频“这不是……而是……”“不是……是……”等AI模板句；
- 交付时能简短说明“选择了什么核心、哪些来源分别贡献了什么”。
- 各段顺序与已确认推进链一致；如在生产中改变主机制、核心或火点，合并成一张新的《生产决策卡》请用户一次确认，不静默改写。

## 3. 灵魂创作

旧任务中的“灵感创作”按本模式兼容执行。

### 目标

让用户产生内容，内容编导负责引导和整理。爆款文本库提供市场问题、公共冲突、传播机制与表达参照；正文的核心判断、故事、经历、原话和价值取舍来自用户。

### 输入

- 与本条问题相关的市场材料（如有）及其来源状态；
- 与当前方向、目标人群和经营任务相关的真实问题或传播机会；
- 用户已有的口述、Live 对话、笔记、原始稿、真实事件或回答；
- 用户确认的公开边界。

### 引导顺序

先复用用户已有的口述、笔记、原始稿和核心判断。材料足够且判断已确认时跳过补充访谈，按生产资料门预检并补齐本条生产决策后整理成稿；以下提问步骤仅处理真实缺口。没有可用市场样本时按资料门标记未校准，不因此要求用户重述。

1. 从已有本人材料或可用爆款文本库提取一个具体问题、冲突或用户场景，只作为对话入口；
2. 向用户提出一个能打开真实经验的具体问题，优先问事件、选择、代价、转折和当前判断；
3. 用户表达时先完整承接，不抢答、不提前总结、不用连续问题打断；
4. 每轮只追问一个会增加事实、冲突、判断或边界的问题；
5. 把用户原话分为事实、感受、判断、故事、方法、边界和未知；
6. 材料足够后先返回“核心内容提取”，让用户确认真正想讲什么；
7. 用户确认核心后，再从爆款文本库选择适合的钩子、框架、情绪推进和表达机制；
8. 生成问题提纲、半逐字稿或高保真整理稿；只有用户明确要求完整逐字稿时才生成完整稿；
9. 用户校准事实、立场、口吻和最终表达后，才标记为可拍摄候选。

### 硬边界

- 用户尚未产生核心内容时，不生成完整逐字稿；
- 不把爆款作者的答案、故事和观点写成用户的内容；
- 不用人格数据库里的标签替用户完成本轮判断；
- 不把AI追问后的推测写成用户事实；
- 用户说“先听我讲”时停止总结和生产，继续承接原始表达；
- 没有故事时可以使用用户已经讲清的观点、方法、清单或案例分析，但核心仍由用户产生。

### 完成判断

- 至少有一个具体事件、真实问题或明确经验起点；
- 用户已经确认本条的核心判断；
- 稿件中的关键事实和立场能追溯到用户原始内容；
- 爆款文本只贡献传播机制和市场连接，没有替用户发明内核；
- 用户能够指出稿件里哪些话是自己真正想说的。
- “本次拍法”来自用户可执行的真实形式；需要第二角色、场景或关键画面时已具备相应素材，或明确停在待补状态。

## 4. 评论区素材

评论区可提供：

- 用户真实问题；
- 核心情绪与用户原话；
- 具体场景和个人故事；
- 认同、反对与质疑；
- 原内容没有回答完的追问；
- 新的选题和内容线索。

内部保留评论来源，并区分用户原话与作者观点。高保真模式慎用；混合二创可以将其作为主要素材来源之一；灵魂创作用它选择对话入口和理解用户问题，不能用评论替用户产生核心内容。

## 5. 初稿检查与转化

### 第一轮检查顺序

1. 开头是否抓人；
2. 这篇稿件到底解决什么问题；
3. 内容火了以后可能带来多少目标客户；
4. 转化模块是否已经自然埋入正文。

### 当前确认的转化暗线

转化不只是结尾行动号召，也包括正文里对作者能力的证明：

1. **我是谁、我做过什么**：把相关身份、项目经历和成绩自然藏进正文；
2. **我是如何解决这个问题的**：展示作者解决问题的方法、过程或能力；
3. **第三部分待确认**：不得由AI自行补成正式规则。

所有身份、成绩、项目和结果必须来自人格数据库或用户确认，不得由AI虚构。

### “不像本人”的处理

先检查AI生成的口吻和表达方式，用代表性内容与 Live 自然表达重新校准。若口吻调整后仍不像本人，不继续做表面润色，标记为整个生产工作流需要在内部测试中回查。

## 6. 已确认与待验证边界

### 已确认

- 除单条明确高保真快速执行外，每轮《生产决策卡》必须明确三种模式中的一种，不沿用上一轮默认选择；模式不单独开启确认轮次；
- 内容生产按高保真、混合二创和灵魂创作分别核验单条资料包；赛道采集批次目标不再充当统一开稿门槛；
- 混合二创可以主爆款为锚，也可以直接从多样本内容池开始；
- 内容池模式先横向提炼答案开放的候选选题并主动推荐一个优先项；用户选择选题并确认按选题合同生成的《生产决策卡》后，再确定唯一核心、生成开头并分配素材；
- 用户确认混合二创并提供完整内容池，不等于授权AI跳过选题与框架闸门直接生成初稿；
- 混合二创不强制加入本人故事，观点拆解、阶段规划、方法组合、清单和案例分析均可成立；
- 爆款的关键问题、强情绪、用户相关主旨和鲜明立场应尽量保留；
- 只有与当前IP确认立场冲突时，才需要重新选择；
- 用户口吻来自代表性内容和 Live 自然表达；
- 初稿先看开头、问题与转化；
- 转化暗线目前确认了两部分。

### 待验证

- 三种模式的完整推荐矩阵与更多切换口径；
- 灵魂创作引导问题的实际效果和对话轮数；
- 评论区在灵魂创作中的具体进入方式；
- 故事改编、沿用和第一人称演绎的操作口径；
- 转化模块第三部分；
- 产品承接的完整生成方法；
- 改稿工作流的内部异常排查；
- “可拍摄”与“可发布”的完整验收合同；

### 已确定的下游交接

- 用户确认逐字稿后，自行完成拍摄、剪辑、封面和字幕；
- 用户导出成片后，将视频文件与对应逐字稿一并交回操盘手；
- 操盘手的 `jiangdao-publish` 生成平台标题、推送语和标签候选，用户选择并明确授权后调用平台上传 Skill；
- “选择候选”不等于“授权发布”，只有真实平台返回才能记录为已发布。
