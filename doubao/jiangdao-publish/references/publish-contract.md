# 视频发布准备与上传合约

执行方式与授权先后顺序统一读取 [平台操作与发布方式合同](../../shared/platform-operation-contract.md)。小红书、抖音、快手、Bilibili 均支持 `authorized_upload`；`manual_handoff` 用于用户选择人工操作或实际能力不可用时。

## 1. 状态机

```text
等待成片
→ 已收到成片与逐字稿
→ 发布候选待选择
→ 已选择待授权
→ 按 delivery_mode 分流
  ├─ authorized_upload：已授权待检查 → 上传中 → 已发布 / 发布失败 / 结果待核验
  └─ manual_handoff：待本人发布 → 本人反馈已发布待核验 / 已发布
```

不得跳过“已收到真实成片与逐字稿”。不得把“已选择待授权”写成“已发布”。

## 2. 输入记录

每次任务记录：

- 视频文件路径、文件名、版本或导出时间；
- 对应逐字稿及来源；
- 目标平台和账号名；
- 当前经营任务、目标人群和承接方式；
- 《经营发布计划》版本、当前内容在组合中的角色与统一 CTA（如有）；
- 用户已提供的封面、发布时间、产品链接或其他平台字段；
- 敏感事实、隐私、版权和禁止表达。

视频与逐字稿明显不是同一内容时停止生成候选，请用户确认正确版本。只做基本文件与对应关系检查，不擅自重剪、重做字幕或覆盖视频。

## 3. 平台发布清单

每个平台分别维护：

- 平台、账号、成片版本和 `delivery_mode`；
- 当前内容在《经营发布计划》中的角色、CTA 与承接方式；
- 标题、推送语、标签候选与最终选择；
- 封面、分区、产品链接、发布时间等平台字段；
- 候选选择、发布授权、登录和上传状态；
- 真实链接、内容 ID、失败原因或待核验动作。

操盘手决定经营目标、内容组合、顺序和调整条件；内容编导决定具体选题、结构和逐字稿；本 Skill 只管理平台候选、发布字段、授权、上传和结果留痕。

## 4. 发布候选合同

每个平台分别生成候选。默认三组：

| 组合 | 目标 | 约束 |
|---|---|---|
| A 操盘手推荐 | 同时服务当前经营任务与内容传播 | 默认排第一并说明推荐理由 |
| B 偏传播 | 强化用户进入理由、冲突或具体结果 | 不捏造热点、数据或夸张事实 |
| C 偏精准与信任 | 明确目标人群、问题和作者能力 | 不虚构身份、成绩、产品或承诺 |

每组必须是可以整体选择的完整组合：

- **标题**：对外标题，不把逐字稿首句机械截取成标题；
- **推送语**：补充观看理由、核心价值或承接，不复述整篇逐字稿；
- **标签**：与主题、人群、问题和当前平台相关；不默认加入“热门、爆款、必看”等无依据标签；
- **选择理由**：一句话说明更适合什么经营目标。

平台字符限制、禁用项和实时规则可能变化。自动上传平台在操作前按当前界面或上传工具核验；人工交接时使用公开说明、用户截图或人工校验，缺失时标明待检查。

## 5. 用户选择与授权

识别以下不同表达：

| 用户表达 | 状态变化 | 动作 |
|---|---|---|
| “选 A” | 已选择待授权 | 保存组合，不上传 |
| “A 的文案，C 的标签” | 已选择待授权 | 合并并回显最终组合，不上传 |
| “选 A 并发布” | 自动上传：已授权待检查；人工交接：待本人发布 | 按所选方式检查后上传或交付材料 |
| “就用这个发” | 按平台方式分流 | 对最近一次回显的组合执行自动上传检查或人工交接 |
| “明晚八点发” | 待补完整定时时间 | 补齐日期、时间、时区与平台，按授权及工具契约安排 |

复用当前会话中可追溯、未撤销且覆盖同一平台、账号、成片、最终文案和时间的明确发布授权；选择与授权可以分属不同轮次，不机械增加重复确认。存在多账号、多平台、定时歧义或最终文案尚未回显时，先消除会造成误发的歧义。

## 6. 平台路由

| 平台 | 执行 Skill | 通用字段 | 额外字段 |
|---|---|---|---|
| 抖音 | `douyin-upload` | 视频、标题、推送语、标签、账号 | 可选封面、定时、产品链接与产品标题 |
| 小红书 | `xiaohongshu-upload` | 视频、标题、推送语、标签、账号 | 可选封面、定时 |
| 快手 | `kuaishou-upload` | 视频、标题、推送语、标签、账号 | 可选封面、定时 |
| Bilibili | `bilibili-upload` | 视频、标题、推送语、标签、账号 | 必填分区 ID，可选定时 |

仅对 `authorized_upload` 平台读取并调用上传 Skill 的当前命令契约，或使用用户指定且实际可用的发布工具，并遵守其访问限制。本表只负责操盘手交接，不替代平台 Skill。

多平台发布时：

- 为每个平台生成适配候选；
- 分别确认账号和必填字段；
- 按平台方式分别调用或人工交接并记录结果；
- 一个失败不覆盖其他平台的真实成功状态。

## 7. 发布前检查

最低检查项：

- 视频文件仍存在且是用户选定版本；
- 逐字稿与视频版本对应；
- 平台与账号唯一；
- 最终标题、推送语、标签已回显；
- CTA、产品链接和商业承诺有真实来源；
- 隐私、版权和禁止表达未被候选文案重新引入；
- 自动上传平台账号登录有效；人工交接只记录用户提供的账号，不自动验证登录；
- 目标平台必填字段齐全；
- 立即发布或定时发布明确；定时包含日期、时间和时区。

## 8. 发布结果记录

每个平台分别保存：

- 发布状态：待本人发布 / 本人反馈已发布待核验 / 已发布 / 发布失败 / 结果待核验；
- 平台、账号和执行时间；
- 视频文件版本；
- 最终标题、推送语、标签及其他实际提交字段；
- 平台链接、内容 ID 或返回记录；
- 失败错误、未知项和下一步检查动作。

只有平台真实返回或本人提供且能核对当前账号、成片版本与最终文案的发布证据支持时，才能写“已发布”。人工交接材料已完成可以交付，但不能算实际发布完成。发布链接和版本交给 `jiangdao-review` 做内容复盘；涉及阶段、方向、产品、价格、渠道或资源投入的信号交给操盘手最终判断。
