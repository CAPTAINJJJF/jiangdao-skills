# 爆款样本拆解卡合约

本合约定义完整后台拆解卡。用户可见的字段名和顺序统一引用共享的 [内容编导前台文本格式合同](../../shared/content-frontstage-format-contract.md)。后台可以保留更细的证据、框架与关联，但必须沿同一条推理链组织：

`先还原原作 → 再理解赛道问题 → 再还原选题加工 → 区分原选题与作者答案 → 再判断传播 → 用评论验证和继续挖题 → 最后沉淀资产`

字段没有证据时写 `不可得（原因）`、`待核实（原因）` 或 `不适用`，不为了完整制造判断。

## 前台可读性闸门

后台拆解卡可以完整，面向用户的阅读版必须让用户在不读逐字稿的情况下理解原作，并知道这条研究下一步怎样使用：

- 每篇标题下先写“内容概览”和“内容推进”。内容概览用自然语言还原原作起点、主要论证、作者答案和最终落点；内容推进显示实际讲述顺序。
- `07 作者答案` 先给一句话答案，再用连贯叙述说明作者怎样讲清楚。抽象步骤清单只能补充，不能替代内容还原。
- `08—09` 只展示足以支撑判断的核心依据、代表评论和最多两个新问题；完整反证、评论分类和证据明细留在后台。
- `10 最值得拿走` 只选择一个主要资产，说明具体借法、暂不借什么和下一步用途。数据库增量映射与完整资产清单留在后台。
- 技术验收、字段缺失和数据库状态压缩成会影响理解的一句证据说明，避免后台管理信息占据前台主体。

## 01 来源与数据

固定保存：

- 平台、作者、原标题、原始链接；
- 发布时间、采集时间；
- 点赞、评论、收藏、转发及其他平台可见数据；
- 入选依据与当前数据门槛；
- 正文/逐字稿、视觉、评论的获取状态；
- 关键数据缺口。

可见数据只证明来源内容整体获得过传播。没有点击、留存、完播、粉丝基线或对照实验时，不把某个具体元素写成已经验证的传播原因。

## 02 推送语与推送标签

分开保存：

- 原始推送语；
- 平台推荐文案；
- 原作话题标签；
- 采集时真实使用的搜索词；
- 平台可见标签或分类；
- 每项证据状态与来源。

原标题、推送语、推荐文案、话题标签、搜索词和平台标签不得互相代填。搜索词若来自本轮采集任务，明确标记为“采集搜索词”；没有平台推送语、推荐文案或标签时写不可得，不由 AI 补写。

## 03 完整逐字稿

详情页内部必须直接保存：

- 完整逐字稿、完整正文或按顺序排列的逐页 OCR；
- 原始发布文案；
- 角色清单及待核实角色；
- 开头与结尾原文证据；
- 必要的关键视觉信息；
- 原始媒体、封面、图片、字幕或视觉证据入口。

这一节只负责还原原作，不做分析。机器 ASR 或 OCR 保留待人工复核状态，不覆盖原始证据。

### 条件触发：形式处理

纯单人口播默认可直接使用，不增加前台字段。出现对话、采访问答、情景演绎、画外音配画面，或价值明显依赖动作与关系时，后台只记录一个状态及一句理由：

- **直接使用**：内容离开原形式后仍自然成立；
- **转译形式**：需要改为第一人称复盘、故事讲述或场景演练；
- **保留原形式**：关系、表演或画面本身就是主要价值。

## 04 赛道问题

`赛道问题` 是旧后台字段 `现实/基础问题` 的统一新名称。它描述这条内容背后，赛道用户真实存在、可以反复开发且能够产生多个选题的问题。

赛道问题通常比原选题高一个抽象层级。原作只是在某个人群、阶段或场景中呈现了这个问题时，先抽掉该样本特有的对象、做法和标题包装，保留多个相关场景都会遇到的核心矛盾；再由 `05 选题怎么来的` 说明作者怎样把它收窄成当前原选题。原作本身已经讨论赛道级问题时，不为追求抽象继续上提。

后台同时记录：

- 赛道问题；
- 目标用户；
- 问题发生的阶段、场景或时机；
- 用户为什么在意；
- 核心情绪及其对象与触发点；
- 问题证据及其身份：正文、评论、访谈、咨询、搜索、发布复盘或 AI 候选归纳；
- 证据缺口。

赛道问题不能使用宽泛行业名、标题包装、作者答案或抽象关键词代替。只有作者正文时，可以还原“候选赛道问题”，但必须标明缺少真实用户信号；作者自问自答、剧情对白和 AI 推断不能冒充目标用户原话。

固定做三项层级检查：

1. 同一个赛道问题能否在当前赛道内长出至少三个对象、阶段或场景明显不同的选题；只能长回当前原题时，通常仍写得过窄；
2. 当前原选题能否被解释为这个赛道问题的一种具体发生方式；两者没有清晰从属关系时，需要重做；
3. 问题中是否混入作者的方法、结论或价值判断；混入后退回作者答案层。

上提后的赛道问题超出当前单条样本直接证据时，标为“赛道问题候选”，并说明本文只验证了哪个具体场景；不能借抽象层级扩大市场证据。

好问题只检查三项：

- 与目标用户有关；
- 答案不显然；
- 知道答案后会影响判断或行动。

## 05 选题怎么来的

这一节回答作者怎样把普通的赛道问题加工成当前原选题。识别标准统一读取 [选题加工三条规则](../../jiangdao-adapt-topic/references/topic-processing-rules.md)。

后台记录：

- 加工动作：未明显加工 / 元素迁移 / 选题具体化 / 收益显化 / 损失显化，可多选；
- 保留的核心需求；
- 作者新增或收窄的人群、对象、阶段、场景、行业、时间或限制条件；
- 显化的收益或损失；
- 标题、推送语、正文、视觉或其他直接依据；
- 判断强度与待核实项。

只识别原作者实际使用的动作。不能为了让分析显得完整，反向补出作者没有使用的迁移、收益或损失；AI 认为“还可以怎样加工”属于下游改造线索，不写进本节的原作还原。

## 06 原选题

原选题说明作者最终选择讨论的对象、场景和待解释问题：

- 保持答案开放，允许不同创作者给出不同答案；
- 删除作者专属的原因、结论、方法和标题修辞；
- 一个样本只还原一个主要原选题；
- 原始标题、推送语和开头钩子只作为包装证据另行关联。

固定检查：`赛道问题 → 选题加工 → 原选题` 是否能够顺着证据解释。无法解释时，不硬造加工关系，写“未明显加工”并保留缺口。

## 07 作者答案

集中提炼作者面对原选题实际给出的内容：

- 核心答案；
- 核心观点与立场；
- 方法、步骤或行动答案；
- 适用条件与作者明确说出的边界；
- 支撑答案的人物、动作、案例、数字、原话、顺序、代价和转折；
- 内容框架、实际推进链和表达怎样承载答案；
- 长故事的段落功能或产品转化桥，仅在原作真实存在时记录。

后台保留完整字段，前台必须装配为：`一句话答案 → 作者怎样讲清楚 → 必要的关键方法或判断 → 适用边界`。“作者怎样讲清楚”按原作顺序还原内容，读者无需回看逐字稿也能知道作者具体讲了什么。

观点、立场和方法属于作者答案，不能回填到赛道问题或原选题。事实、研究、数据和作者经历分别记录来源；AI 补充解释固定标为 AI 推断。

内容框架按共享合同记录：

```text
内容框架：
实际推进链：
可借部分：
```

原作题目可借与框架可借分开判断。框架还要记录所需原料、当前 IP 是否具备以及具体可借哪一段。

## 08 为什么能传播

这一节在读完赛道问题、选题加工、原选题和作者答案后再判断。允许自由分析，不套固定标签或机械评分。

可能成立的因素包括：

- 问题本身需求强；
- 题面收益或损失清楚；
- 答案、观点、故事或表达具有新意；
- 信息压缩、收藏或执行价值高；
- 时代背景、作者身份、标题、推送语、视觉或平台分发；
- 其他有直接证据支持的因素。

每条判断同时保存：

- 传播判断；
- 支持依据；
- 反证或替代解释；
- 结论强度；
- 数据与证据边界。

后台可以使用“停下来、看下去、获得价值、互动/承接”帮助分析过程，但前台统一写成自然的“为什么能传播”。只要证据足以比较，就给出优先判断；证据不足到无法排序时说明并列原因。评论区证据留到下一节验证，不提前混写成用户进入或看完的原因。

## 09 评论区洞察

只使用真实取得的评论，承担“验证、补充、继续挖矿”三项任务。固定分析：

- **用户在回应什么**：用户接住了原作的哪一部分；
- **评论原话**：典型且有信息量的真实表达，并保留来源与可见互动；
- **验证或修正传播判断**：评论支持、削弱或改变了上一节的哪些判断；
- **新赛道问题**：评论继续暴露了哪些可反复开发的问题；
- **新选题线索**：哪些评论本身可以发展成下一条内容；
- **评论证据边界**：有效评论数、可见范围、缺失与偏差。

后台还可以归档具体场景、情绪表达、补充故事、认同、反对、质疑、表达借用、传播动作和咨询/产品信号。泛化夸赞、纯表情、重复内容和营销灌水不计入独立用户问题。评论不可得时保留缺口，不用作者正文或 AI 推断补齐。

## 10 最值得拿走

后台记录这条爆款真正值得沉淀的完整资产；前台只选择其中一个主要资产。后台资产可以包括：

- 一个赛道问题；
- 一个选题加工方法；
- 一个作者答案或解释；
- 一个内容框架或实际推进机制；
- 一个具体表达、故事、人物关系或关键原料；
- 一个传播机制及证据边界；
- 一个评论区新问题或新选题线索。

每项资产必须记录：

- 资产内容；
- 资产类型；
- 来源证据；
- 值得拿走的理由；
- 可直接借 / 需改造 / 仅作观察；
- 下游需要补充的 IP 资产或条件；
- 沉淀去向及与样本、赛道、拆解版本的关联。

前台固定回答：`主要带走 → 具体借法 → 暂不借 → 下一步用途`。主要带走必须帮助用户形成一个明确动作；数据库映射、候选状态和其他次要资产保留在后台。

“最值得拿走”不等于照抄标题。拆解阶段只沉淀研究资产和改造线索，不替当前 IP 确认最终选题、故事归属、生产方式或传播结果。

## 当前判断与交接

后台继续保留：

- 当前拆解版本、输入状态和人工确认状态；
- 选题是否可进入共创；
- 选题可借鉴性与框架可借鉴性；
- 形式处理；
- 事实、AI 推断与待核实项；
- 来源、视觉、评论和数据缺口；
- 写入赛道问题池的完整问题句、来源索引与证据状态。其他拆解资产保留在详情页和后台索引，用户选中题目后再按生产需要调用。

## 批量汇总

批量任务逐篇完成 01—10，再按 [赛道数据库统一模板](../../jiangdao-content/references/track-database-template.md) 增量更新四部分赛道认知库与后台选题加工库。单条拆解负责提供可追溯增量，赛道级结论必须经过跨样本归并与证据审计。

每张当前版本拆解卡同时向 [赛道数据库通用编译合同](../../jiangdao-content/references/track-database-compilation-contract.md) 提供结构化单条增量：来源记录、完整赛道问题、作者答案、真实评论原话、原作实际加工动作和单条传播信号。单条增量不写赛道理解、问题归并结果或正式传播规律。

### 《爆款借鉴索引》

保存来源、赛道问题、选题加工、原选题、作者答案、传播判断、评论验证、最值得拿走、建议动作和证据边界，用于排序、检索和下游调用。

### 数据库增量映射

赛道认知库、后台选题加工库、状态和升级条件只读取赛道数据库统一模板。拆解阶段只输出以下映射，不复制聚合规则：

| 单条拆解增量 | 写入位置 | 初始状态 |
|---|---|---|
| 赛道问题及证据身份 | 后台问题池；跨样本归并后更新赛道问题池 | 候选问题或有用户证据的问题 |
| 原作实际选题加工 | 后台选题加工库 | 单样本加工候选 |
| 原选题、评论新题线索、最值得拿走 | 单条详情、《爆款借鉴索引》和当前任务证据 | 研究资产，不自动生成候选选题 |
| 真实评论原话、追问、争议与反对 | 后台用户语言与评论证据；归纳后更新用户回应地图 | 按原证据状态写入 |
| 单条“为什么能传播” | 后台传播信号候选 | 跨样本复核后才进入赛道传播规律 |
| 跨样本空白、时效和 IP 适配线索 | 后台聚合缺口和当前任务资料包 | 由内容编导结合当前任务审计 |

### 其他研究资产

作者答案、观点、方法、框架、推进链、表达、故事与人物机制继续保存在单条详情、《爆款借鉴索引》和来源关联中，供赛道认知归纳与选题确认后的生产决策调用；选题共创只读取赛道问题池。

### 证据缺口

列出来源、推送语、标签、全文、视觉、评论、角色、行为数据和事实核验缺口。不沿用历史评分表，也不因样本出现次数不同自行增加验证等级。

跨样本空位统一保存在后台聚合缺口，不自动生成候选选题。逐篇 01—10 始终保留为证据入口。
