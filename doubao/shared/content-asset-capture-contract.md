# 内容资产捕捉与跨库关联合同 V0.1

## 目标

让本我、内容编导和其内部子 Skill 在当前任务中识别可复用资产，并把本人证据与市场证据分别交给对应数据库维护者。内容种子是一组共享字段和联合查询条件，不单独建库，也不新增分身。

本合同只处理当前任务已经获得的对话、链接、复盘、访谈或文件。全局安装且允许隐式触发的本我分身，可以在其他当前任务出现高信号本人证据时作为旁路采集方共同处理；这仍局限于当前可见材料。未打开的聊天、旧任务历史和未来消息不会被后台监听，额外会话需由用户提交记录、分享链接或由产品集成显式传入。

## 1. 捕捉结果

每个候选片段只产生一种处理结果：

- `忽略`：寒暄、操作指令、临时安排、无信息重复或无法安全归属；
- `新增`：形成新的可追溯资产条目；
- `合并`：核心问题、立场和目标场景与已有条目一致，只追加新来源、案例、证据或边界；
- `关联`：主题相关，但立场、对象、场景或用途存在实质差异，保留独立条目并建立关系；
- `暂缓`：归属、来源或公开边界存在会改变写入结果的具体疑点。

## 2. 高价值候选

出现下列信息时进入判断，不代表自动升级为稳定结论：

- 用户第一次说出的判断，或反复出现并得到新证据的判断；
- 有人物、场景、选择、结果或代价的真实经历；
- 强烈感受及其发生时的具体画面、念头和行为；
- 用户问题、市场反馈、评论原话、反对意见和真实咨询信号；
- 被用户纠正的常见解释、反常识理解或稳定立场；
- 已形成步骤、判断标准、适用边界或案例的方法；
- 可被定位、产品、课程、内容或复盘再次调用的原话与表达方式。

只有同时满足“归属可判断、来源可追溯、信息能独立理解、对未来任务有复用价值”时才新增或合并。出现次数只说明重复出现，不自动证明市场强度、稳定人格或方法有效。

### 本我负责挖掘的三类种子

- **认知种子**：用户自己的判断、疑问、解释、认识变化或尚未想通的矛盾；保留其依据与尚待展开之处，不要求先有成熟观点。
- **情绪种子**：用户主动表达的情绪，以及与之相连的具体事件、念头、选择或在意；不要追问感受和身体反应，也不代写隐藏动机。
- **经历种子**：真实经历中值得继续展开的一幕、选择、转折、结果或代价；片段可以先成为种子，不要求先讲完整个人故事。

三类是内容种子的来源分类，可以重叠，不另建种子库，也不要求每次凑齐。本我深挖时主动识别线索，通过具体事实、选择、前后变化及有依据的候选理解帮助展开；仅倾诉、明确停止或不保存时遵守用户边界，不为收集种子延长对话。

种子保留原话、具体语境和一个尚可继续展开的点，后续可据此发展新的命题；已有候选命题时须与原始种子分开标注，不能写成用户已经认同的观点。种子尚未成熟也可按证据条件捕捉，不自动成为选题或脚本。

## 3. 统一字段

两库可使用不同存储形态，但内容资产条目至少兼容以下字段：

| 字段 | 规则 |
|---|---|
| `asset_id` | 所属数据库内的稳定主键；已有主键直接复用 |
| `seed_id` | 仅内容种子填写；跨库关联时两边使用同一个值 |
| `seed_type` | 本人种子按材料标注认知 / 情绪 / 经历，可多选；已有条目缺少时按证据补充，不凭空补齐 |
| `asset_type` | 经历 / 故事 / 感受 / 观点 / 判断 / 方法 / 问题 / 案例 / 表达 |
| `canonical_statement` | 用一句话说明条目核心；不得替换用户原话或证据原文 |
| `source_refs` | 来源类型、链接或文件、消息/段落定位、时间、说话人 |
| `evidence_state` | 材料事实 / 用户原话 / AI 提炼 / AI 观察待验证 / 个人判断待市场验证 / 市场证据 / 当前未知 |
| `seed_tag` | 是 / 否；只表示具有创作潜力 |
| `seed_maturity` | 已捕捉 / 待补证据 / 可立题 / 可生产 / 暂停 |
| `public_boundary` | 私密 / 可匿名 / 可公开 / 待确认 |
| `related_asset_ids` | 关联的人格、市场、任务或内容记录 ID |
| `creation_state` | 未选题 / 选题中 / 已选题 / 生产中 / 已发布 / 已复盘；没有下游动作时留空 |
| `updated_at`、`revision` | 最近更新时间与修订关系；保留历史失效原因 |

标签、成熟度、证据状态、公开边界和创作状态分别维护，不用一个标签同时表达多种状态。

## 4. 分流与写入权限

### 人格数据库

写入本人经历、感受、选择、价值判断、能力证据、稳定立场、方法、原话和表达特征。本我拥有写入权；其他 Skill 只生成带来源的本人增量交接包。

### 赛道与内容数据库

写入目标用户问题、市场反馈、外部样本、平台信号、内容结构、市场观点、候选方法和真实发布复盘。内容编导拥有写入权；其他 Skill 只生成带来源的市场增量交接包。

### 双库关联

同一材料同时形成本人判断与市场命题时，两库各写一个符合自身用途的条目，并共享 `seed_id`。两边不得复制成同一句话：人格条目回答“这体现了本人怎样的经历、判断或表达”，市场条目回答“它对应什么用户问题、内容机会或待验证机制”。

外部作者的经历、观点和业绩不能进入人格数据库；用户基于外部材料形成的本人判断可以进入。市场候选缺少外部证据时标记“AI 提炼 / 待验证”或“个人判断 / 待市场验证”，不得写成市场规律。

## 5. 查重、合并与修订

按以下顺序处理：

1. 先用来源链接、文件定位、消息位置或内容 ID 查精确重复；
2. 再比较核心问题、立场、目标对象和具体场景；四项一致时优先合并；
3. 新片段只增加案例、解释、证据或边界时，追加到原条目并提高版本；
4. 主题相同但立场、对象或场景不同，建立关联并保留两条；
5. 新证据与旧判断冲突，保留旧版本、冲突来源和当前结论；
6. 用户纠正后记录失效原因，不静默删除历史。

## 6. 内容种子调取

内容编导收到“最近有什么值得拍”“从最近聊天里找选题”“调出内容种子”等请求时：

1. 锁定当前项目与本人身份；无法确定活动人格数据库时，只说明缺口，不读取案例或演示数据库代替；
2. 联合读取人格数据库中 `seed_tag=是` 的条目和赛道数据库中可关联的问题、证据与机会；
3. 排除已发布且没有新增角度、公开边界不允许、来源不清或与当前经营任务冲突的条目；
4. 按本人表达强度、证据完整度、目标用户相关性、当前经营任务、时效和生产成本排序；
5. 最多展示 3 条候选，每条给出种子原点、市场连接、当前成熟度、还需要用户补充什么和推荐理由；
6. 用户确认一条后，先匹配赛道问题池中的完整问题句；匹配成功时只把该问题句交给选题共创，匹配失败时保留为内容种子并补充赛道问题。选题确认后再读取本人材料和其他研究资产形成《生产决策卡》；调取本身不生成逐字稿。

## 7. 自动化边界

- 当前任务中识别到的本人增量自动交给本我，市场增量自动交给内容编导；各维护者按现有证据与版本规则写回。
- 本我旁路采集先做高信号门控，门槛通过后才读取活动人格数据库；原任务保持主体，捕捉不增加第二个下一步。
- 捕捉和标签不自动改变方向、定位、观点、公开边界、选题、发布或经营决策。
- 没有活动数据库、处于演示模式或用户明确要求试跑时，只生成模拟分流结果，不写入真实数据库。
- 周期扫描、跨会话监听、外部消息订阅和自动发布需要用户另行授权与配置。
