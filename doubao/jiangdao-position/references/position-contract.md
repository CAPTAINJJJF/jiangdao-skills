# 《IP 定位与最小产品卡》合约

## 定位定义

```text
为哪类人
+ 解决什么问题
+ 提供什么结果
+ 用什么性质的产品或服务
+ 如何收费与承接
```

方向决定“面向谁、讲什么”；定位决定“解决什么、卖什么、怎么服务和收费”。

## 进入条件

本合同只接收 B1－产品形成与 B2。B1－账号启动仅有启动锚点、尚无明确问题、需求信号或产品意图时，交回操盘手进行真实表达与反馈验证；不生成本合同的产品卡。本人明确要求设计产品可作为产品意图，但仍按证据缺口记录未知需求。阶段与执行模式沿用操盘手已确认的输入；历史记录仅写“B1”时先区分子阶段。

## 输出结构

1. 版本、日期、B1－产品形成 / B2 状态、进入依据和上游方向版本。
2. 当前方向：目标群体与内容主题。
3. 目标用户、场景、核心问题和可感知结果。
4. 本人的经历、背书、结果、信任基础和待验证能力。
5. 最小产品：名称、性质、核心承诺、范围、交付方式、周期、责任边界与适配条件。
6. 价格假设、成本和承接能力；不得写成已验证事实。
7. 现有替代方案、市场信号、反证和高影响缺口。
8. 本人作为第一个用户的桥接实践（适用时）。
9. 最快成交路径候选及选择依据。
10. B 进入 C 所需证据：产品体系与可核验真实成交；交付状态另记。
11. 用户需要确认的产品、价格、公开与成交闸门。

## 状态

- B1－产品形成：群体与主题已选，已有明确问题、需求信号或产品意图 / 最小产品草案。
- B1－账号启动：只做回传标记，不生成最小产品卡；具体行动由操盘手调度。
- B2：产品待确认 / 产品待成交 / 成交测试中。
- 已真实成交：交回 `jiangdao-ip` 判 C，不在本 Skill 内宣布产品成熟。

## 证据边界

- 课程大纲、课件、报价或口头意向不等于真实成交。
- 一次成交允许进入 C，但不证明交付效果、复购、规模或长期需求。
- 同行卖得好不等于当前用户能复制其流量、信任或交付。
- 获客与成交路径必须结合价格、信任成本、适配沟通和现有渠道选择，不预设固定公域或私域链路。
- 定价必须考虑结果、替代方案、信任、责任风险、交付成本和真实销售反馈。
