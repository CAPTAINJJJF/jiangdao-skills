# 发布复盘合约

## 必需输入

最终发布版本、平台、账号、链接或发布记录、发布时间，以及至少一类真实反馈。

## 数据快照

保存时点、曝光/播放、完播/停留、点赞、评论、收藏、分享、主页访问、私信、线索、成交、成本和本人感受。不可得字段保持为空。

## 爆款数据解释辅助框架

当复盘对象是已发布后的高表现内容，除了记录完整数据快照，可用以下框架帮助解释数据，但不得用单条内容直接宣布永久规律：

把不同指标分别作为选题、人群、注意力、互动、传播和商业承接的候选信号。任何单一指标都不能直接等同于需求、信任或因果结论；结合账号基线、内容版本、观察窗口和其他证据解释。

使用方式：

- 先看高表现内容里“已经成立”的部分，再判断哪些结构值得复刻；
- 复盘爆款时，不只问“为什么火”，还要问“它能不能拆出下一组内容”；
- 对失败内容保持必要记录，但避免把大量时间耗在自我否定式解释里；
- 如果播放高但涨粉低，优先检查账号定位、主页承接和内容是否真正指向“人”；
- 如果播放高但完播低，优先检查开头承诺、中段推进和信息密度；
- 如果评论里出现高频追问、反驳或误解，优先进入下一轮选题池。

## 六层复盘

1. 内容层；
2. 目标用户层；
3. 承接层；
4. 商业层；
5. 表达与效率层；
6. 风险层。

## 结论标签

事实 / 对比发现 / 可能解释 / 待测试假设。

## 固定输出

本节字段是后台复盘记录。用户可见《发布复盘卡》的标题、栏目、字段顺序和缺省写法统一引用共享的 [内容编导前台文本格式合同](../../shared/content-frontstage-format-contract.md)，不得把以下后台字段平铺到前台形成第二套模板。

- 内容主动作：保留内容机制 / 改写表达 / 换内容角度 / 调整内容承接表达 / 停止当前内容假设；
- 下一轮唯一主变量；
- 保持不变的条件、观察时点和停止标准；
- 自动写回赛道与内容数据库的增量及修订记录；
- 交给本我分身的本人特点、表达或公开边界证据；
- 交给操盘手分身裁决的用户、产品、价格、线索、经营与风险信号。

只调整未来任务，不覆盖历史结果。

内容主动作只约束下一条内容测试，不得据此直接改变 A/B/C、方向、定位、产品、价格、渠道投入或经营资源分配。涉及这些事项时只记录证据和建议交接，最终经营判断由 `jiangdao-ip` 完成。

## 多条内容横向复盘

每条内容先独立记录：主假设、目标人群、唯一 CTA、主指标、观察窗口、真实结果和证据限制。达到首批或计划复盘点后再增加横向矩阵：

```text
内容 ID / 主假设 / 主指标 / 实际结果 / 目标用户原话 / 支持或反证 / 下一步
```

横向判断规则：

- 播放、点赞、收藏、评论、材料提交、咨询、成交和交付分别记录，不相互替代；
- 用户复述内容概念只能证明即时理解；能在自己的真实任务中正确使用，才是更强的概念掌握证据；
- 一条内容低表现先检查表达、分发与样本量，不直接否定方向；
- 多条内容验证同一假设时，明确控制条件和差异，不把相关性写成因果；
- 只修改尚未生产或尚未发布的未来内容，已发布版本和原计划保持可追溯。
