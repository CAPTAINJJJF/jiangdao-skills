# 跨项目旁路采集

## 目标

当用户在其他项目、专业任务或其他 Skill 的对话中自然暴露与本人有关的高信号证据时，让本我分身作为旁路采集方出现。原任务继续推进；本我只完成信号判断、来源记录和必要写入。

这项能力依赖当前任务已经可见的内容和 Skill 的隐式触发。它不读取未打开的聊天，不在后台持续监听，也不追溯扫描所有历史任务。

## 启动门槛

当前片段至少满足下面一项，才进入归属和查重：

- 发生过的关键选择、转折、拒绝、妥协及其理由、代价或结果；
- 带具体场景的喜欢、反感、坚持、边界或不愿牺牲；
- 用户连续纠正 AI 后显露出的稳定判断标准、协作偏好或表达偏好；
- 有案例、行为结果或外部评价支持的能力证据；
- 与旧认识形成明显补充、冲突或变化的新事实；
- 多条事实开始共同指向一个正向或负向盲区线索；
- 可复用的本人故事、判断、方法、比喻或代表性原话。

以下内容直接忽略，不读取人格数据库：

- 寒暄、导航、格式、文件操作、界面调整和一次性执行指令；
- 仅为当前交付提出的局部偏好，且没有重复证据或人格意义；
- 一次即时情绪、无具体场景的自我标签或没有结果的计划；
- 用户粘贴、翻译、分析的外部观点，且没有形成明确本人判断；
- 学员、客户、家人、案例人物或虚拟角色的经历；
- 为录课、测试、盲测或演示而说出的模拟内容。

上面的“忽略”仅表示不进入旁路采集与长期人格库；当前主角色仍应回应用户的真实情绪。用户转而请求情绪疏导时，按 [情绪疏导与心力恢复](emotional-support.md) 直接承接，不以入库门槛拒绝支持。

## 身份与数据库路由

先用当前路径、任务名称、说话人、项目主体、第一人称语境和既有身份线索判断材料归属，再决定是否读取数据库。

读取 [使用者配置与可选运行环境](../../shared/runtime-configuration.md)，按配置定位候选人格库；只有当前材料明确属于配置身份，且没有演示、学员或第三方主体信号时，才能跨项目写入。当前工作空间中已有归属明确的数据库时优先复用，不混读其他人的资料。

身份或真源有冲突时，只形成当前允许范围内的待归属候选，不读取争议数据库，也不宣称已经持久化。用户要求不保存时不生成待入库文件。

## 处理顺序

1. **完成原任务**：保持原 Skill 的目标、交付和唯一下一步。
2. **门控**：只看当前可见片段是否达到高信号门槛；未达到即结束旁路采集。
3. **判归属**：区分用户本人、第三方、案例、演示与外部观点；争议片段暂缓，其余可靠片段继续。
4. **查重**：门槛通过后才读取活动人格数据库，按来源、核心判断、对象和场景判断 `忽略 / 新增 / 合并 / 关联 / 暂缓`。
5. **分层记录**：事实和原话写入相应层级；AI 连接写为 `AI 观察 / 待验证`；计划不得写成行动结果。
6. **安排后续**：需要更多证据的盲区线索进入待验证区，可在持续认识中自然补证，也可成为每日复盘候选。
7. **前台提示**：只有已经可靠写入或合并时，才追加一行简短提示；不展开访谈，不追加第二个下一步。

## 最小记录字段

旁路写入或候选包至少保留：

- `captured_at`：捕捉时间；
- `source_task`：项目、任务或可追溯消息位置；
- `speaker_and_owner`：说话人与人格归属；
- `raw_evidence`：事实或用户原话；
- `signal_type`：经历、选择、边界、能力、纠错、变化、表达或盲区线索；
- `evidence_state`：材料事实、用户原话、AI 提炼、AI 观察待验证或当前未知；
- `capture_result`：忽略、新增、合并、关联或暂缓；
- `public_boundary`：默认仅内部使用，除非已有明确公开边界；
- `related_asset_ids`：已有条目或内容种子关系。

同一轮出现多个相关信号时合并成一条来源记录。实质新增或修订才升级人格数据库版本；精确重复、措辞变化和无新证据不升级。

## 前台形式

可靠写入时，在原任务答案之后、原任务唯一下一步之前，最多出现一行：

```text
【本我捕捉】已记录：<一条事实、原话或待验证线索>
```

提示只说明记录了什么，不当场下人格定论。盲区达到正式标准后，也优先留给持续认识或每日复盘完整呈现，避免在专业任务中突然改变对话主题。

## 功耗控制

- 每轮先用当前消息做轻量门控，门槛通过后才读取人格数据库；
- 不为普通任务加载完整历史，不扫描兄弟项目和旧聊天；
- 每个回复最多形成一条合并记录和一行前台提示；
- 不因捕捉自动调用对话搭子，不生成新任务或行动清单；
- 每日复盘集中处理待验证线索，减少零散深挖和重复写入。
